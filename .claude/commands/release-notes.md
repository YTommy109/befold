# /release-notes — リリースノート生成

前回タグからのコミットを元にリリースノートを生成する。

引数: $ARGUMENTS（dev | stable）— 省略時は対象タグ（最新タグ）に `-` が
含まれるかどうかで自動判定する（含む: dev / 含まない: stable）。

## 1. タグの取得

```bash
git tag --sort=-v:refname | head -2
```

- 最新タグと前回タグを取得する
- タグが 1 つしかない場合は初回リリースとして全コミットを対象にする

## 2. コミットログの取得

```bash
git log {前回タグ}..{最新タグ} --pretty=format:"%s" --no-merges
```

## 3. リリースノートの生成

生成方針は dev / stable で異なる。

### dev（pre-release）の場合

これまで通り、Conventional Commits のプレフィックスで全コミットをグループ化して
Markdown 形式で出力する:

```markdown
## {最新タグ}

### Features
- 項目（feat: から）

### Bug Fixes
- 項目（fix: から）

### Others
- 項目（上記以外）

---

## {最新タグ}（日本語）

### 新機能
- 項目（feat: から）

### 修正
- 項目（fix: から）

### その他
- 項目（上記以外）
```

該当がないグループは省略する。英日の併記については「4. 言語」を参照する。

### stable（一般リリース）の場合

**ユーザーに影響のある内容だけ** を対象にする。開発・運用に関する内容（CI/CD、
テスト、リファクタリング、ドキュメント、ビルド設定、依存関係の更新、内部ツール
など）は、コミットの種類に関わらず含めない。

1. 各コミットについて、ユーザー（アプリの利用者）から見て挙動や体験が変わるか
   を判断する。
   - 含める例: 新機能の追加、UI/UX の変更、ユーザーが遭遇する不具合の修正、
     パフォーマンス改善（体感できるもの）
   - 除外する例: `chore:` `test:` `docs:` `ci:` `refactor:` `style:` の接頭辞、
     および `feat:`/`fix:` であっても内部実装・開発体験・CI・テストのみに
     関する変更（例: 「quality-loop のイテレーション上限を明確化する」
     「コーディング規約を更新する」）
2. 判断に迷うコミットはユーザー影響がないものとして除外する（安全側に倒す）。
3. 除外したコミットがある場合は、リリースノート生成後にユーザーへ一覧を
   提示し、含めるべきか確認する。
4. 残ったコミットを Markdown 形式で出力する:

```markdown
## New Features
- 項目

## Fixes
- 項目

---

## 新機能
- 項目

## 修正
- 項目
```

該当がないグループは省略する。ユーザー影響のあるコミットが 1 件もない場合は
その旨をユーザーに報告し、リリースノートの内容について確認を取る。

## 4. 言語（英語を先、日本語を後）

**リリースノートは英語セクションを先に、日本語セクションを後に書く。**
両者は同じ項目を過不足なく対応させ、片方にだけある項目を作らない。

理由は 2 つ。

- リポジトリの基準が英語であること。直下は `README.md`（英語）と
  `README.ja.md`（日本語）で、英語が基準・日本語が別ファイルという形になっている。
- 配布サイトが英日バイリンガルで、英語ページからもリリースノートへ飛ぶこと。
  `site/src/views/releases.tsx` は `lang` で出し分けるが、「変更点」列のリンク先は
  `site/src/lib/github.ts` の `notesUrl`（GitHub のタグページ）で言語別に分かれない。
  日本語だけのノートだと英語読者が読めないページに着く。

GitHub のリリース body は 1 本しか持てないため、README のようなファイル分割は
できない。**同一 body 内で英語 → `---` → 日本語**の順に並べる。

なお Sparkle のアップデートダイアログにはこの body は出ない
（`.github/workflows/release.yml` の `generate_appcast` はリリースノートを
渡していない）。読者は GitHub と配布サイト経由の人間だけである。

`CHANGELOG.md` は日本語のみで維持する（`.claude/skills/changelog.md` を参照）。
リリースノートから**日本語セクションだけ**を取り出して追記する。
