# /worktree-reset — worktree を保ったままブランチを切り直す

引数: $ARGUMENTS（省略可。`[新ブランチ名]` | `--force` | `--no-fetch` | `--keep-branch`）

PR がマージされ、リモートブランチが削除された後に、**同じ worktree のまま**次のタスク用の
ブランチを `origin/main` 起点で切り直す。完了判定・保護・切り替えはすべてスクリプト内で行われる。

## 手順

1. 現在の worktree で実行する:

   ```bash
   scripts/worktree-reset.sh $ARGUMENTS
   ```

2. 出力（旧ブランチ・新ブランチ・起点コミット）をそのままユーザーに報告する。

スクリプトがエラーで終了した場合はエラーメッセージを報告して終了する（勝手にリカバリーを試みない）。
特に「未マージです」で止まった場合は、**`--force` を自分の判断で付け直さない**。作業が失われるため、
ユーザーに確認する。

安全策（スクリプト側で担保、把握しておく）:

- 未コミットの変更があれば `--force` でも中断する
- メインリポジトリ（worktree でない側）では実行を拒否する
- 旧ブランチが `main` の祖先でなく、かつ旧ブランチが自身の merge-base から変更した
  ファイルのいずれかが `main` の現在の内容と一致しない場合、`--force` なしでは中断する
- 新ブランチ名が既存ブランチと衝突する場合は中断する

補足:

- 新ブランチ名を省略するとランダムな 2 語（例: `juniper-flint`）が自動生成される
- squash merge された PR は `main` の祖先にならない。この場合は旧ブランチが変更した
  ファイルすべてが `main` の現在の内容と一致するかで完了を判定する（中身を見るため、
  上流の追跡状態 `[gone]` は判定に使わない）。**`[gone]` は「リモートブランチが
  削除された」ことしか意味せず、squash merge 後にそのローカルブランチへ別の
  未プッシュコミットを積んだ場合は安全の根拠にならない**（実例: TASK-528 参照）
- worktree ごと捨てたい場合は `/worktree-clean` を使う
- 切り直してよいか分からない場合は、先に `/worktree-status` で未コミット変更と
  PR の状態を確認する（読み取り専用）
