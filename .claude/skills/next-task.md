## next-task

CLAUDE.md に定義された「自律的なタスク進行のための運用ルール」の優先順位に
従い、次に着手すべきタスクを機械的に判定する。

### 優先順位

1. ユーザー向けの不具合（GitHub Issues）が未対応なら最優先
2. 着手可能な backlog タスクのうち、他の作業をブロックしているもの
3. 着手可能な backlog タスクのうち、着手順（登録順・依存関係）が早いもの

この基準で決められない場合のみユーザーに確認する。

### Steps

1. `gh issue list --state open --label bug` 等で未対応の GitHub Issues を確認する。
   1件でもあれば、それを最優先候補として提示する。
2. GitHub Issues に該当がなければ `backlog board` で着手可能なタスク一覧を確認する。
   - 「着手不可」（レビュー待ち・他タスク完了待ち・仕様未確定などが notes に
     記載されている）タスクは、その理由が解消しているか確認した上で対象外とする。
   - 他タスクの `blocked-by` 依存元になっているタスクを優先する。
3. 2 でも決まらない場合は、backlog 上の登録順（ordinal / 作成日）が早いものを選ぶ。
4. 候補タスクとその選定理由（どの優先順位ルールに合致したか）を提示し、
   着手してよいかユーザーに確認する。
5. 基準1〜3のいずれでも一意に決まらない場合（同率の候補が複数残る場合）は、
   判定を打ち切りユーザーに選択を委ねる。
