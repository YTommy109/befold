## 前提

裏付けの種類を括弧で示す。

- 差分は前後 1,000,000 行の文脈付きで取得し、差分本文に旧版・新版の全文が入る
  （コード参照: `GitDiffReader.wholeFileContextLines`）
- 差分の取得と JS への送信は差分モード（`showsDiff`）のときだけ。レンダリング表示に
  差分が届くのはレンダリング差分モードのときに限られる（コード参照:
  `ViewerDiffPresenter.refresh`、`DocumentSurfaceStack.diffState`）
- 表示モードは TASK-483 で `rendered` / `source` / `diff` / `renderedDiff` の 4 つになった。
  CSV/TSV は TASK-483.2 で `renderedDiff` を持った（ドキュメント参照: TASK-483 の Notes）
- markdown-it のブロックトークンは `map = [開始行, 終了行)` を持つ（実測: markdown-it の
  `parse` が段落・見出し・リスト・フェンス・表の開きトークンに `map` を付ける）
- CSV のレンダリング差分は、行をまとめた単位（レコード）ごとに「変更あり」を判定し、
  削除単位と追加単位を文書順に並べる（コード参照: `viewer-src/csv-diff.ts`）

## 方式: A（新旧の単位を文書順に並べる）を採る

差分本文から旧版・新版の全文を復元し、それぞれを markdown-it で `parse` する。
トップレベルのブロック（`level === 0` の開きトークンから、対応する閉じトークンまで）を
1 単位とし、`map` でソース行の範囲を持たせる。CSV のレコードと同じ手順で、

- 反対側に「まったく同じ文脈行だけを覆うブロック」がある → 文脈（新版のものをそのまま描く）
- それ以外の旧ブロック → 削除ブロック
- それ以外の新ブロック → 追加ブロック

を文書順に並べる。同じ位置では削除を先に置く。「削除行を含む旧ブロック／追加行を含む
新ブロック」で判定すると、削除だけ・追加だけの変更（リストの項目を 1 つ足す、空行を
足して段落が割れる）で片側にしか色が付かない。行→単位の割り当てと並べ替えは
CSV と共通の関数にする（CSV のレコードは全行を覆うが、Markdown のブロックは
空行を覆わない。単位の境界が変わらない空行だけの変更は描画に現れないので色を付けない）。

各単位は、その側の `parse` で得たトークン列の切り出しを `md.renderer.render` に渡して
HTML にする。`env`（参照リンクの定義）は同じ側の `parse` のものを使う。出力は連結した
全体に 1 回だけ、通常の Markdown 表示と同じ `sanitizeRenderedHtml` を通す（ブロックごとに
通すと、ブロックをまたぐ `<details>` などがブロックの中で閉じられる）。

### 採らなかった案

- **B: 旧版と新版を左右に並べる**: 実装は最小だが、どこが変わったかは目視任せで
  「変更のあったブロックが色分けして表示される」（TASK-483 AC #2）を満たさない
- **新版だけを描き、削除は件数などで示す**: 削除された段落の中身が読めない。
  ソース差分へ切り替えないと何が消えたか分からず、レンダリング差分の意味が薄れる
- **ブロック内の語単位の強調**: レンダリング後の DOM とソースの文字位置の対応が
  インライン記法（強調・リンク）で崩れる。まずブロック単位で成立させる

## 削除ブロックの見せ方

**削除ブロックも描いて削除色を付ける。** 文書は実物より長くなるが、何が消えたかを
レンダリングされた形のまま読める。ソース差分の表と同じく「旧 → 新」の順に並ぶ。

- 変更ブロックは `<div class="md-diff-block diff-add|diff-del" data-diff-block="n">` で包む。
  地色と左端の帯で示し、色だけに頼らないよう帯の外側に `+` / `-` を出す
- 削除ブロックの中の `id` / `name` 属性は外す（生 HTML のものも含む）。見出しのアンカーと見出しジャンプが新版の見出しを
  指すようにするため（旧版の見出しと同じ slug が二重に現れる）

## 差分モードの意味

TASK-483 の決定に従う。Markdown は `diff`（⌘3）がソース差分のまま残り、
`renderedDiff`（⌘4）がレンダリング差分になる。ソース差分は失われない（TASK-483 AC #4）。
`FileType.supportsRenderedDiff` に Markdown を足す。

## レイアウト切替（inline / side-by-side）

レンダリング差分では効かせない。常に 1 カラムで描く（CSV と同じ）。
`ViewerCapabilities.canToggleDiffLayout` は既にソース相当の表示中にしか立たない
（TASK-483.2）ので、Markdown でも追加の分岐は要らない。

## 差分ジャンプ

`data-diff-block` は変更ブロックを包む `div` に付ける。番号は「削除の連なり + 直後の
追加の連なり」を 1 ブロックとして数える（CSV・ソース差分と同じ畳み方）。

## 段階読み込みとの関係

表は差分の全文から組むため、`_renderMarkdown` は実際に描いた形（`'diff'` /
`'markdown'`）を返し、`render()` がそれを記録する。`appendChunk` は既存の
`shape() === 'diff'` で追記しない（DOM の形では判定しない。TASK-339 の再発を避ける）。

## 生 HTML がブロックをまたぐとき

`<details>` と `</details>`、`<div align="center">` と `</div>` のように開きタグと閉じタグが
別ブロックにある場合は、閉じるまでのブロックを 1 単位にまとめる（タグの開閉は `html_block` の
内容から数える）。開きタグだけのブロックを差分の `div` で包むと、包みの閉じタグの位置で
中の要素まで閉じられ、通常のレンダリング表示と入れ子が変わる。代わりに、中の 1 段落だけの
変更でも `details` 全体が削除 + 追加として出る（リスト・表と同じ扱い）。

## スクロール位置の記憶

レンダリング表示（⌘1）とレンダリング差分（⌘4）は、ファイルごとのスクロール位置の記憶を
共有する（記憶のキーは `ViewerBridge.ViewMode` の rendered / source の 2 値）。差分側には削除
ブロックが挟まるので、切り替えると位置は厳密には一致しない。ソース表示（⌘2）と差分（⌘3）も
同じ理由で既に共有しており、それに揃えた。

## 既知の限界

- 参照リンクの定義行（`[x]: https://…`）はトークンを作らないため単位に属さない。
  定義だけを書き換えた変更は色が付かない（リンク先が変わった段落は文脈として描かれる。
  実測: 上の `parse` で定義行に対応するトークンは無かった）
- リストや表はトップレベルで 1 単位なので、項目 1 つの変更でもリスト全体が
  削除ブロック + 追加ブロックとして出る

## 縮退

差分が無い・壊れている・全文差分でない（ハンクが 1 つでない、開始行が 1 でない）
ときは通常のレンダリング表示に落とす。
