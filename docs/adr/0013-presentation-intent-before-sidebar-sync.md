## Context

ツリー表示で Quick Open（⌘P）から、表示中ルート配下の畳まれたサブフォルダー内の
ファイルを開くと、本文の位置にフォルダー一覧が一瞬重なる（#794）。

### 原因（実測 / 2026-11-24 時点）

本文に何を出すかは `FileListModel.previewTarget` が決める。これは
`PreviewTargetResolver.resolve` が、サイドバーの選択と一覧の行から導いた値である。
選択したファイルに対応する行がまだ一覧に無いと、導出は「選択が古い」とみなして
`.folder(currentDirectory)` を返す。

ツリー表示では、サブフォルダー内の行は祖先を展開して初めて一覧に載る。展開は非同期で
着地するため、その間だけ本文がルートの一覧に置き換わる。`SidebarNavigator` に
Quick Open と同じ順序で切り替えを流し、`previewTarget` が通る値を記録した結果は次のとおり。

| 表示形式 | 開いたファイル | `previewTarget` の遷移 |
|---|---|---|
| ツリー | ルート配下の畳まれたサブフォルダー内 | `file` → **`folder(base)`** → `file` |
| ツリー | ルートの外 | `file` → `undetermined` → `file` |
| リスト | どちらも | `file` → `undetermined` → `file` |

実機でも、ちらつきはツリー表示でだけ起きた。

### 同じ型の 3 件目である

「選択に対応する行が無い ⇒ フォルダー表示」の判定は、これまでに 2 回、例外を足して
直してきた。

- TASK-445: フォルダー移動の直後で一覧の取り直しが未着のとき → `isListingCurrent` を追加
- TASK-468: 開いている文書の親フォルダー行を推論で引いていた → 推論をやめて選択を確定させる

GitHub #794 も同じ判定が誤発火したもので、ツリー向けの例外を足す修正（PR #795）は
マージせず閉じた。例外を足すたびに、別の入口で同じ型が残る。

### 他の入口にも同じ型がある（コード読解 / 2026-11-25 時点・未実測）

本文の表示を変える入口を 15 か所洗い出した。ファイルを開いたのに本文がフォルダー一覧に
落ちる候補が、#794 のほかに少なくとも次の 5 つある。いずれもコードを読んだ結果で、
実機では確かめていない。

1. Quick Open やリンクで、表示中フォルダーにあるが行の無いファイル（不可視ファイル・
   作成直後のファイル）を開く。`SidebarNavigator.syncAfterSwitch` は親フォルダーの
   一致だけで「移動不要」と判断し、一覧も取り直さない。次の再読み込みまで一覧が残る
2. フォルダー一覧を表示中の窓で、すでに開いているファイルを CLI・Finder・Quick Open
   から開き直す。同じ URL への切り替えは早期 return するため、一覧のまま変わらない
3. 元の窓の一覧を引き継いで新しいタブを開いたとき、新しいファイルが引き継いだ一覧に
   無いと、最初の再読み込みまで一覧が重なる
4. 開いているファイルの名前を変えると、再読み込みの着地で一覧が選択より先に書かれる。
   一瞬フォルダー表示に倒れ、タイトルが変わり、フォーカスがサイドバーへ移る
5. ツリーで祖先フォルダーを畳む・レイアウトを切り替えるなど、選択の行が消える操作でも
   本文が変わる

### 決定と実装の向きが逆になっている

ADR 0002 の規約 1 は「提示状態は 1 つの値で持ち、`FileListModel.selection` は
その投影であって独立した真実にしない」と決めた。実装は逆で、提示状態
（`PreviewTarget`）を選択から導いている。そのため、サイドバーの同期の遅れが
そのまま本文の表示に伝わる。

### 入口の意図と実際の動作がずれている（コード参照）

- `befold <ディレクトリ>` はフォルダー一覧を出さず、フォルダー内の最初のファイルを開く
  （`SupportedFileResolver.resolveFileToOpen`、`DocumentOpener.openViewer`）
- リスト表示でフォルダー D に入ると、D の一覧ではなく、以前の選択か先頭の項目を
  自動で選ぶ（`SidebarNavigator.navigateToFolder`）。結果として、ファイルが開く、
  サブフォルダーの一覧が出る、空タブがファイルに置き換わる、のいずれかになる

## Decision

**本文に何を出すかは、入口が書く「意図」で決める。サイドバーは、その後で意図に合わせる。**
サイドバーの選択・一覧の行・展開の状態から、本文の表示を導かない。

1. **意図は窓ごとに 1 つの値で持つ。** 「文書 URL を出す」か「フォルダー URL の一覧を
   出す」のどちらかを表す。`PreviewTarget` はこの値から導き、サイドバーの状態を材料にしない
2. **意図を書くのは、利用者の操作を受けた入口だけ。**
   - 文書: CLI・Finder・最近使った項目・ドロップでファイルを開く、Quick Open、
     サイドバーや本文の一覧でファイルを選ぶ、文書内リンク、隣のファイルへの移動
   - フォルダー: サイドバーでフォルダー行を選ぶ、フォルダーに入る・上へ移動する、
     本文の一覧でフォルダーに入る、`befold <ディレクトリ>`
   - 戻る・進む: 記録した意図を再生する
   - 例外（2026-11-26 追記 / TASK-930.7）: 一覧を出しているフォルダーが削除・改名で
     無くなったときは、窓が `.file` へ書き直す（文書タブは開いている文書、ディレクトリを
     開いた窓は空タブの画面）。契機は窓のキー復帰と履歴の再生で、判定はディレクトリが
     実在するかという事実で行う。サイドバーの同期が書かない点（決定 3）は変わらない
3. **サイドバーの同期は意図を書かない。** 一覧の再読み込み・展開と折りたたみ・
   レイアウトの切り替え・不可視ファイルの切り替え・フォルダー移動の後追いは、選択を
   意図に合わせるだけにする。行がまだ無ければ、選択の強調が遅れるだけで、本文は変わらない
4. **ファイルを開く経路の順序は、意図を書く → 本文の読み込みを始める → サイドバーを
   合わせる、で揃える。** サイドバーは、リスト表示ならフォルダー移動とファイルの選択、
   ツリー表示なら祖先の展開とファイルの選択を行う
5. **フォルダーに入ったら、そのフォルダーの一覧を出す。** 記憶した選択や先頭の項目を
   自動で選んでファイルを開く動作はやめる。`befold <ディレクトリ>` も同様に、
   そのディレクトリの一覧を出す

ADR 0002 の決定（提示状態を 1 つの値で持ち、能力をそこから導く）は維持する。
本 ADR は、その提示状態を何から決めるかを定め直す。

## Consequences

### 良くなること

- 「行がまだ無い」「一覧が未着」を判定の材料にしなくなる。#794 と、Context に挙げた
  5 つの候補が同じ形で消える。例外の追加を繰り返す必要もなくなる
- 本文の表示とサイドバーの同期が独立する。サイドバーの非同期処理の順序や世代の
  追い越しが、本文に影響しない
- `befold <ディレクトリ>` とフォルダーへの移動が、利用者の操作どおりの結果になる

### 変わる挙動（利用者に見える）

- `befold <ディレクトリ>` は、最初のファイルを開かず、フォルダー一覧を出す
- リスト表示でフォルダーに入ると、そのフォルダーの一覧が出る。記憶していた選択の
  復元や、先頭の項目を自動で開く動作は無くなる
- ツリー表示で祖先フォルダーを畳んでも、本文は変わらない

### 移行

一度に置き換えず、backlog のサブタスクに分けて段階的に移す。各サブタスクの
実装前に `/review-design` を回す。

- (a) 意図の型を入れ、`PreviewTarget` を意図からだけ導く
- (b) ファイルを開く経路を、決定 4 の順序に揃える
- (c) フォルダーに入ったときの動作を決定 5 に揃える
- (d) `befold <ディレクトリ>` でフォルダー一覧を出す
- (e) 戻る・進むの履歴を意図で記録・再生する

`.undetermined`（一覧の未着を表す値）が残るかどうかは (a) で決める。意図は窓の
生成時に入口が書くため、不要になる見込みである。結果: (a)（TASK-930.1）で削除した。

### 却下した案

- **ツリー表示で、ルートより深い位置の行が無ければ「未確定」とする（PR #795）**:
  #794 は消えるが、行の有無で本文を決める形は残る。Context の他の候補は直らない
- **行が無いときは常に「未確定」とする**: リスト表示で空フォルダーへ移動した後の
  再読み込みは、選択を開いているファイルへ戻し、この判定でフォルダー一覧を出している。
  反転すると、この経路で本文が文書へ戻ってしまう
- **選択が開いている文書と一致すれば文書を出す**: 上の空フォルダーの経路では、
  選択がまさに開いている文書になる。2 つの状況を区別できない
