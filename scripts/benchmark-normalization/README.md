# テキスト正規化の配列拡張ベンチマーク

大きなテキストを EOF まで読み進めるときの `NormalizedTextCache` の割当コストを比較する。
本番コードは `consume(window:)` の容量予約だけを削除し、`Array.append` の幾何級数的な容量拡張に任せる。
毎窓 `count + window.count` を予約すると、必要な最小容量に近い拡張を繰り返してコピーが増える。
ファイル全体の事前予約は行わず、初期プレビューの遅延正規化を維持する。

## 測定範囲と検証
<!-- derived-from #実測2026-10-31 -->

- ファイル読込後から、ハッシュ計算・エンコーディング判定・デコード・増分正規化・行オフセット生成が EOF に達するまでを計時。
- `normalizeFully: false` / `oneShotLoad: false` で、現在の正規化済みバイト数 + 1 を繰り返し要求する。
- EOF 時 RSS は `mach_task_basic_info.resident_size`、ピーク RSS はその時点の `getrusage.ru_maxrss`。入力 Data とキャッシュを生存させて測る。ピークはプロセス起動・ファイル読込も含む。
- CSV の索引作成・検索・描画・WebKit は含まない。アプリ全体のメモリ削減率を示すものではない。アロケータが解放済み領域を保持する詳細機構は未特定。
- 正規化後の全文コピーと SHA-256 検証は別プロセスで実行し、計測に混ぜない。前後とも Python の独立した CRLF/CR → LF 変換と全文 SHA-256・バイト数・行数が一致。
- CI にメモリや時間の閾値は追加しない。既存の Swift テストを強化し、4 窓以上の遅延成長、窓をまたぐ CRLF / UTF-8、全行オフセット、末尾改行、チャンク再構成を確認する。
- 表示仕様・共有範囲・正規化タイミングは変わらないため、現在仕様の設計文書の更新は不要。

## 再現手順

リポジトリルートで実行（macOS / Swift / Python 3、追加 Python 依存なし）。他のビルド・テストが終了してから実行する。

```sh
python3 scripts/benchmark-normalization/run.py --base 38afdff0 --runs 3
```

`scripts/make-large-csv.py` の固定 seed 生成器と、このディレクトリの生成処理だけで合成入力を作る。
実データは読み込まない。変更前のソースは `git show`、変更後は作業ツリーから取り出して同じハーネスで最適化ビルドする。
生成入力・バイナリ・新しい結果は gitignore 対象の `.tmp/normalization-benchmark/` に出力する。
異なる入力を使う場合は、サイズや改行分布により効果が変わる。
