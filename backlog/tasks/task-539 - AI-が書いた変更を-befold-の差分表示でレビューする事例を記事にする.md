## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
コーディングエージェント（Claude Code など）に書かせた変更を、人が befold で読んでレビューする往復を事例記事にする。**医療費控除の記事（TASK-538）と対になる題材。**

## なぜ TASK-538 と別に立てるか

| | TASK-538（医療費） | このタスク |
|---|---|---|
| 対象 | iCloud Drive のフォルダ | git 管理下のリポジトリ |
| 差分表示 | **使えない**（git 管理外） | **主役** |
| 見せ場 | TSV の表・PDF・Markdown | 差分表示・「変更のあるファイルのみ」・自動リロード |
| 読者 | 確定申告をする人 | コーディングエージェントを使う開発者 |

TASK-538 の Description に『差分表示は使えない題材』と明記してあるとおり、あちらでは差分に触れられない。両方揃うと befold の機能を過不足なく覆える。

## 素材（2026-08-22 のセッションで実際に起きたこと）

このタスクを起票した作業そのものが素材になる。記録が消える前に残す。

- **往復の形**: Claude が Markdown を書く → `befold-review` スキルが befold で開く → 人がレンダリング結果を読む → 指摘を出す → Claude が直す → befold が自動リロードして同じウィンドウで続きを見る
- **実際の指摘数**: README.md（349 行）への 1 回目のレビューは『十分です』、2 回目に **6 点**の指摘（節の削除 2 件・手順の追加 1 件・文言の変更 1 件・別タスクへの切り出し 1 件・前提の誤り 1 件）
- **人が読まなければ出なかった指摘の例**: 『providers.md は確定申告に関係しない』『把握しておくべき制約は Dropbox 比較の残滓』——どちらも文章として読んで初めて気づく類で、テストや lint では出ない
- **差分の規模**: PR #583 が 9 コミット。その後のブランチが 3 コミット・15 ファイル・+852 -27 行
- **入口**: `.claude/skills/befold-review` スキル（TASK-521 で公開配布を検討中）が『レビューを依頼する直前に befold で開く』を自動化している

## 正直な穴（記事にする前に埋める必要がある）

**このセッションでは差分表示を実際には使っていない。** 人がレビューしたのは新規ファイルと更新後の全文で、差分ビューを開いてはいない。記事の主役に据えるなら、次を実際に通して確かめること。

- 変更のあるファイルだけをサイドバーで絞り込み、差分を順に読む
- 比較基準が『デフォルトブランチとの merge-base』であること（`BefoldApp/befold/App/GitComparisonBase.swift:24`）が、エージェントのブランチ作業とどう噛み合うか
- レビュー指摘 → 修正 → 自動リロードで差分が更新される、の往復

## 素材が消えるタイミング

差分のスクリーンショットを撮るなら**ブランチがマージされる前**。マージ後は merge-base が動いて差分が空になる。撮り直すには同等の変更を持つブランチが要る。
