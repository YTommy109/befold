## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
コーディングエージェント（Claude Code など）に書かせた変更を、人が befold で読んでレビューする往復を事例記事にする。**医療費控除の記事（TASK-538）と対になる題材。**

## なぜ TASK-538 と別に立てるか

| | TASK-538（医療費） | このタスク |
|---|---|---|
| 対象 | iCloud Drive のフォルダ | git 管理下のリポジトリ |
| 差分表示 | **使えない**（git 管理外） | **主役** |
| 見せ場 | TSV の表・PDF・Markdown | 差分表示・「変更のあるファイルのみ」・自動リロード |
| 読者 | 確定申告をする人 | コーディングエージェントを使う開発者 |

TASK-538 の Description に『差分表示は使えない題材』と明記してあるとおり、あちらでは差分に触れられない。両方揃うと befold の機能を過不足なく覆える。

## 素材（2026-08-22 のセッションで実際に起きたこと）

このタスクを起票した作業そのものが素材になる。記録が消える前に残す。

- **往復の形**: Claude が Markdown を書く → `befold-review` スキルが befold で開く → 人がレンダリング結果を読む → 指摘を出す → Claude が直す → befold が自動リロードして同じウィンドウで続きを見る
- **実際の指摘数**: README.md（349 行）への 1 回目のレビューは『十分です』、2 回目に **6 点**の指摘（節の削除 2 件・手順の追加 1 件・文言の変更 1 件・別タスクへの切り出し 1 件・前提の誤り 1 件）
- **人が読まなければ出なかった指摘の例**: 『providers.md は確定申告に関係しない』『把握しておくべき制約は Dropbox 比較の残滓』——どちらも文章として読んで初めて気づく類で、テストや lint では出ない
- **差分の規模**: PR #583 が 9 コミット。その後のブランチが 3 コミット・15 ファイル・+852 -27 行
- **入口**: `.claude/skills/befold-review` スキル（TASK-521 で公開配布を検討中）が『レビューを依頼する直前に befold で開く』を自動化している

## 正直な穴（記事にする前に埋める必要がある）

**このセッションでは差分表示を実際には使っていない。** 人がレビューしたのは新規ファイルと更新後の全文で、差分ビューを開いてはいない。記事の主役に据えるなら、次を実際に通して確かめること。

- 変更のあるファイルだけをサイドバーで絞り込み、差分を順に読む
- 比較基準が『デフォルトブランチとの merge-base』であること（`BefoldApp/befold/App/GitComparisonBase.swift:24`）が、エージェントのブランチ作業とどう噛み合うか
- レビュー指摘 → 修正 → 自動リロードで差分が更新される、の往復

## 素材が消えるタイミング

差分のスクリーンショットを撮るなら**ブランチがマージされる前**。マージ後は merge-base が動いて差分が空になる。撮り直すには同等の変更を持つブランチが要る。

## スクリーンショットの撮り方（2026-08-22 ユーザー判断）

CLI オプション（旧 TASK-540）は取りやめ。差分表示が状態依存であることと噛み合わないため。**AppleScript もしくは人手で撮る。**

TASK-538.3 で実際に使った手順が流用できる。要点は 2 つ。

- `osascript` の `front window` は**意図した befold ウィンドウを指すとは限らない**。実際にこのセッションで、別ドキュメントのウィンドウを移動させる事故を起こした
- CGWindowID を取って `screencapture -x -o -l <id>` で撮るとウィンドウ枠ぴったりで安定する。ID は pyobjc の `Quartz.CGWindowListCopyWindowInfo` で `kCGWindowOwnerName == 'befold'` を絞れば取れる

差分モードへの切り替えだけはキー操作（`cmd+3` 相当）が要り、これは前面のウィンドウに当たる。**撮影対象のウィンドウを前面にしてから**行うこと。

## 撮影の実測（2026-08-23）

ブランチ `basin-zephyr`（origin/main から 7 コミット・23 ファイル・+1,728 -35）を対象に撮影した。

撮れたもの:

- `usecase-review-diff.png` … README.md の差分表示。TASK-538.6 で docs/ の定義を広げた変更が赤/緑で出ている
- `usecase-review-all-files.png` … `site/src/views/` の全 11 ファイル（変更のあるものに A / M バッジ）
- `usecase-review-changed-only.png` … 同じフォルダを 4 ファイルに絞った状態 + shell.tsx の差分

### cmd+3 のキー送信では切り替わらなかった

開いた直後は差分の可用性が未確定でメニュー項目が無効なため、キーストロークが無視される。**メニュー項目を直接クリックする**（`click menu item "Show Changes"`）方法に変えたら確実に動いた。

これは TASK-540（CLI で --diff を指定する）を取りやめた判断の裏付けにもなっている——差分は状態依存で、起動時点の指定と噛み合わない。

### アプリの UI が英語

メニュー項目は "Show Changes" / "Show Changed Files Only" だった。日本語の記事に載せるとメニューだけ英語になる。**公開前に日本語 UI で撮り直すか、そのまま使うかを決める。**

### 後始末

`ShowChangedFilesOnly` は SidebarDisplayDefaults に永続化されるため OFF に戻した（`defaults read` で 0 を確認）。表示モードはファイルごとに保存されるので README.md と shell.tsx は次回も差分表示で開く。

## 記事をドラフトとして書いた（2026-08-23）

`/drafts/ai-code-review`（英語版は `/en/drafts/ai-code-review`）で配信中。TASK-541 で入れたドラフト機能の最初の実利用。

### 記事の骨子

1. **読まないと出てこない指摘がある** — 型検査も lint もテストも通る変更に、人が読むと出る指摘がある。このセッションで実際に出た 6 点のうち 2 つを引用した（『この節はそもそも要らない』『没にした別案の名残では』）。どちらも内容の正誤ではなく『そもそもここに要るのか』を問うもので、機械には出せない
2. **変更のあったファイルだけに絞る** — 11 ファイル → 4 ファイルの実物
3. **差分のまま読む** — 比較の起点がデフォルトブランチとの分岐点であることに触れた
4. **直させて、そのまま見続ける** — 自動リロードで往復が同じ画面で回る
5. **知っておくとよいこと** — git 管理下でだけ使えること、変更が無いと選べないこと、befold は読む専用であること
