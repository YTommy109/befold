## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
プレゼンテーション中に、フォーカスをサイドバーに残したままカーソルキーでファイルを送りたい。本文を広く見せつつ、次の資料へ移る操作はキーだけで済ませたい。サイドバーを畳むとフォーカスの移り先が無くなるので、畳むことでは代替できない。

現在の ViewerSplitViewController は minimumThickness 200 / maximumThickness 360 を init で固定していて、サイドバーを「アイコンの列」まで細くできない。

設計は docs/superpowers/specs/2026-09-04-sidebar-slide-mode-design.md（2026-09-04 合意）。幅に応じた段階的なヘッダー密度（full/compact/minimal）の案は、状態と分岐が増えるため取り下げ済み。minimumThickness は 200 のまま据え置く。
<!-- SECTION:DESCRIPTION:END -->

## 実機実測（2026-09-04）

### サイドバーのビュー階層と thickness の意味

計測は NSLog ではなくファイル書き出しで行った（unified log に出ないことがあったため）。
SidebarTableViewLocator に一時的に祖先ビューの frame をダンプするコードを入れて測定し、測定後に撤去済み。

通常時（autosave 復元値 303pt）のビュー階層:

    SwiftUIOutlineListView x=0.0 w=295.0
    ListCoreClipView / ListCoreScrollView / AppKitPlatformViewHost / NSHostingView<FileListView> x=0.0 w=295.0
    NSContainerConcentricGlassEffectView x=8.0 w=295.0
    _NSSplitViewItemViewWrapper x=0.0 w=303.0

**NSSplitViewItem の thickness が効くのは内容部分であって、見た目の幅ではない。**
wrapper = 内容 + 8 の関係が常に成り立つ（303 = 295 + 8、thickness 46 のとき wrapper 54）。
最初 measuredListInset として 8 を thickness に足していたが、これは二重計上で誤り。
SidebarSlideMetrics.thickness は行の幾何だけ（8×2 + 12 + 2 + 16 = 46pt）にした。
見た目のサイドバー幅は 54pt になる。

### スライドモードの幅の遷移（controller.toggleSlideMode を直接呼んで測定）

    tick=3 sidebarWidth=303.0   （進入前）
    tick=4 sidebarWidth=54.0    （ON）
    tick=6 sidebarWidth=54.0
    tick=7 sidebarWidth=303.0   （OFF → 進入前の幅へ復元）

### autosave が汚れないこと

キー: com.degino.befold の "NSSplitView Subview Frames ViewerSplitView"

1. 通常モード: 303.000000
2. スライドモード中: 303.000000（変化なし）
3. スライドモードのまま NSApp.terminate: 303.000000（細幅は焼かれない）

autosaveName を nil にして書き出しを止める方式が意図どおり効いている。
「autosaveName を再設定したとき AppKit が保存済みフレームを読み直して適用するか」は、
解除時に幅が進入前の値へ正しく戻っていることから実害なしと確認した。

### 補足（今後の落とし穴）

- System Events（AX）による表示メニューの一覧は、スライドモード項目を返さなかったが、
  アプリ内で NSApp.mainMenu をダンプすると
  [スライドモード] hidden=false enabled=true action=toggleSlideMode:
  として存在していた。AX の一覧を根拠にメニュー項目の有無を判断しないこと。
- NSApp.sendAction(_:to:nil,from:nil) はこの構成では responder に届かなかった。
  window.windowController as? ViewerWindowController を直接呼ぶ必要がある。
- /Applications/befold.app が起動していると AX のプロセス指定が紛れる。
