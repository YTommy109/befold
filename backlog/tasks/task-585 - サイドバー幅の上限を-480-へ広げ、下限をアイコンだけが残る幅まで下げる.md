## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
プレゼンテーション中に、フォーカスをサイドバーに残したままカーソルキーでファイルを送りたい。本文を広く見せつつ、次の資料へ移る操作はキーだけで済ませたい。サイドバーを畳むとフォーカスの移り先が無くなるので、畳むことでは代替できない。

現在の ViewerSplitViewController は minimumThickness 200 / maximumThickness 360 を init で固定していて、サイドバーを「アイコンの列」まで細くできない。

設計は docs/superpowers/specs/2026-09-04-sidebar-slide-mode-design.md（2026-09-04 合意）。幅に応じた段階的なヘッダー密度（full/compact/minimal）の案は、状態と分岐が増えるため取り下げ済み。minimumThickness は 200 のまま据え置く。
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 maximumThickness が 480 になり、サイドバーを 480pt まで広げられる
- [ ] #2 minimumThickness が、行の左端アイコンは見えてファイル名が隠れる幅になっている（値は List のインセットを実機で実測して決め、実測値を Implementation Notes に残す）
- [ ] #3 幅から密度（full / compact / minimal）を決める純粋関数があり、閾値の境界がユニットテストで固定されている
- [ ] #4 compact では changedFilesOnly と filter が trailing から overflow へ移り、ユニットテストが配列比較で固定している
- [ ] #5 minimal ではフォルダー名が消え、パスメニューがフォルダーアイコンだけになる（メニューの中身は変わらない）
- [ ] #6 SidebarPathMenuButton の .fixedSize() が外れ、full / compact でフォルダー名が truncationMode(.middle) で省略される
- [ ] #7 full ではヘッダーの見た目と並びが従来どおりであることをユニットテストが確認している
- [ ] #8 maximumThickness が 480 になり、サイドバーを 480pt まで広げられる（minimumThickness は 200 のまま）
- [ ] #9 FileListModel に窓ごと・永続化しない isSlideMode があり、これが唯一の真値である（ViewerSplitViewController は真偽値を持たず幅だけを持つ）
- [ ] #10 表示メニューにチェック付きのスライドモード項目があり、サイドバーが畳まれている間は無効になることを ViewerMenuValidator のテストが固定している
- [ ] #11 スライドモード中にサイドバーを畳むとスライドモードが解除され、SidebarStateStore への自動的な recordToggle が発生しない
- [ ] #12 スライドモード中はサイドバー幅がアイコン幅に固定され、ヘッダーがスライドモードを示すアイコン 1 つに置き換わる。そのアイコンを押すと解除される
- [ ] #13 進入時に closeFilter が呼ばれ、進入直後に FileListModel.tableFocuser.focus() でサイドバーへフォーカスが移る
- [ ] #14 スライドモード中およびスライドモードのまま終了した場合に NSSplitView Subview Frames ViewerSplitView が細幅で上書きされず、解除時に進入前の幅へ戻る（手動確認。実測値を Implementation Notes に残す）
