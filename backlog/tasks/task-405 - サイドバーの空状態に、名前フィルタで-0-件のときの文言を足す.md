## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`SidebarEmptyState`（Viewer/SidebarEmptyState.swift）は **git 絞り込みか否かの 2 分岐しか持たない**。名前フィルタ（filterText）で 0 件になったときは「対応ファイルがありません」側に落ちるため、開ける文書で満たされたフォルダーでも読み込みに失敗したように読める。

これは TASK-287 が git 絞り込みについて直したのと同型の問題が、名前フィルタ側に残っているもの。

## いつ目立つか

ツリー展開（TASK-361.4）でサブフォルダを開いている状態だと、「開いているのに何も無い」ように見えて食い違いがより目立つ。

## 現状

TASK-361.5（ツリー展開時のフィルタの意味）のレビューで発見した既存の欠落。祖先保持の実装はブロックしないため、そちらでは扱わなかった。

## /review-design の結論（実装前レビュー）

- 項目 9: filterText に **デフォルト引数を付けない**。付けると呼び出し元の渡し忘れがコンパイルエラーにならず、片側だけ旧文言のまま残る（TASK-320 と同型）。必須引数にすることを構造上の担保とする
- 項目 1 の留保: 「解除すればすべて表示されます」は元から 0 件のフォルダーでは偽になるが、既存の sidebar.empty.changedFilesOnly.description も同じ断定をしているため非対称を作らず揃える。厳密化には絞り込み前の件数を呼び出し元 2 箇所から渡す必要があり、今回の AC の範囲外
- 項目 2/3/5/6/7/8 は非該当（不変条件・消費経路・順序・高頻度経路・非同期の世代管理のいずれにも触れない）

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 実装

- `SidebarEmptyReason`（noSupportedFiles / gitChangeFilter / nameFilter / gitChangeAndNameFilter）を新設。判定は `SidebarEmptyState.reason(activeGitChangeFilter:filterText:)` の純粋関数 1 箇所だけが持つ
- **文言の割り当ても enum 側（titleKey / descriptionKey / systemImage）へ寄せた**。当初計画では body の switch に置く予定だったが、それだと「理由の判定」しかテストされず、**どの理由にどの文言を割り当てたか**が未検証のまま残る。enum のプロパティにしたことで、キーが xcstrings に実在すること・理由ごとに異なる文言になることまでテストで担保できる
- filterText は必須引数（デフォルト引数なし）。実際に呼び出し元 2 箇所ともコンパイルエラーになり、渡し忘れが構造的に防げることを実測で確認した
- descriptionKey は見出しキーからの文字列連結で組み立てない。`String.LocalizationValue` への補間は書式指定子になりキーとして解決されないため（実装途中で踏んで修正）

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
サイドバー／プレビューの空状態を、git 絞り込みの 2 分岐から「絞り込みなし・git のみ・名前フィルターのみ・両方」の 4 分岐へ広げた。名前フィルターで 0 件になったときに「対応ファイルがありません」と出て、開ける文書で満たされたフォルダーでも読み込み失敗のように読める問題を解消する。

判定と文言の割り当てを SidebarEmptyReason（純粋な enum + computed property）へ寄せ、View は選ぶだけにした。filterText は必須引数にして、呼び出し元 2 箇所への配線漏れがコンパイルエラーになる形で担保している。

検証: ユニットテスト 8 件追加、swift test 1341 件全通過、変更ファイルの swiftlint 指摘ゼロ、swiftformat --lint エラーゼロ。加えて実機の Debug ビルドを AXUI 経由で操作し、名前フィルター単独・名前フィルター + 変更のみ表示の 2 ケースで新しい文言が出ることをスクリーンショットで確認した。
