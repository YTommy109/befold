## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
データセンター由来の自動アクセスが「人間の訪問」として計上されており、人間の訪問数が実態より膨らんでいる。ADR 0004 が定めた再検討条件を既に満たしているため、判別方式を見直す。

## きっかけ（2026-08-16 の実測）

TASK-489.3 で gh-pages 流入を調べる過程で、参照元に `http://befold.degino.com:2052` `:2086` `:8080` `:8880` という Cloudflare の HTTP 代替ポートが各 1 件現れた。実体を D1 で確認したところ、4 件すべてが接続元組織 **Driftnet Ltd**（インターネット全域スキャン業者）で、`ua_summary` は `other`、`os` は NULL、`kind` は `visit`。**ボット判定に該当せず人間として計上されていた。**

範囲を広げて、人間として計上されている visit を接続元組織別に見た結果（上位）。

| 接続元組織 | ua_summary | 件数 | ユニーク |
| --- | --- | --- | --- |
| Meta Platforms Ireland Limited | other | 54 | 53 |
| Amazon Data Services Northern Virginia | Chrome | 31 | 31 |
| ARTERIA Networks Corp. | Chrome | 28 | 9 |
| Amazon Technologies Inc. | Chrome | 24 | 22 |
| Google LLC | other | 15 | 11 |
| (null) | curl | 14 | 2 |
| SAKURA Internet Inc. | other | 12 | 8 |
| Twitter Inc. | other | 8 | 5 |
| DigitalOcean, LLC | curl 等 | 7 | 5 |
| Driftnet Ltd | other | 6 | 6 |

同時点の human visit 総数は 354 件。Meta / Amazon / Google / Twitter / DigitalOcean / Driftnet といったデータセンター・SNS のリンク展開だけで **150 件規模**あり、人間の訪問数の見え方が大きく変わる。

## ADR 0004 との関係

`docs/adr/0004-bot-detection-via-user-agent.md` は「まず User-Agent のトークン判定でボットを分類する。`cf.botManagement` は使わない」と決めた。その理由は妥当だったが、**前提が変わっている**。

ADR 0004 が挙げた再検討トリップワイヤ（同 :103-110）のうち、次が発火している。

1. **「独自ドメインへ移行する、または Bot Management が使える構成になり、`cf.botManagement` が実際に取得できると実測できたとき」** — 独自ドメインへの移行は TASK-476 / ADR 0007 で完了済み。ADR 0004 執筆時点の前提だった「`workers_dev = true` の独自ドメイン無し運用」（同 :30-33）はもう成り立たない。`cf.botManagement` が取得できるかは当時「未実測」のままなので、まず実測する。
2. **「計測結果を llms.txt の要否判断以外の用途（詐称耐性が要る用途）に使う要件が生まれたとき」** — TASK-489 で、旧ホストと GitHub 配布経路を停止してよいかの判断材料に使う予定。停止判断は取り返しがつかないため、人間の数が膨らんだままだと誤った判断につながる。

## 扱いの方針

ADR 0004 の判断を否定するのではなく、**トリップワイヤが発火したので予定どおり再検討する**という位置づけで進める。UA 判定を捨てるとは限らない（`cf.botManagement` が取得できない、または精度が伴わない可能性がある）。実測してから決めること。

`as_org` による事後検算は ADR 0004 自身が想定していた手段（同 :47-49「UA と ASN の食い違いは事後に検算できる」）なので、`cf.botManagement` が使えない場合でも ASN ベースの分類は選択肢になる。

## 注意

- 過去データは遡って分類できない（完全な UA を保存していないため）。ダッシュボードには既に同種の注記があるので同じ形にする。
- ボット除外条件は 1 箇所に集約されている（`site/src/analytics.ts:146` の `HUMAN_ONLY`）。規約テスト `site/test/analytics.test.ts:299` が集約を担保しているので、判定を増やしても集約を崩さないこと。
- 実データの確認は `scripts/analytics-query.sh` を唯一の入口にする（読み取り専用トークンが必要。手順は `site/README.md:274-290`）。
