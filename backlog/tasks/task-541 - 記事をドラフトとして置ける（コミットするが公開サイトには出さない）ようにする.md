## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
記事を書きかけの状態でコミットし、**公開サイトには記事として現れない**状態を作れるようにする。

## なぜ要るか

記事は 1 回では書き上がらない。TASK-538 の医療費記事も、テンプレート・実測・スクリーンショットを別々のタスクで積み上げてから本文に入る。この間、本文のドラフトを

- 手元に置いたままにすると、レビューを頼めず、複数セッションをまたいで失われる
- そのままコミットして公開すると、書きかけが一覧に並び、sitemap にも載る

の二択になる。**コミットはするが公開しない**という置き場が要る。

## 現状（実測）

TASK-538.1 で入れた `site/src/lib/articles.ts` の `ARTICLES` が記事の唯一の列挙で、`site/src/views/usecases.tsx` の一覧は `articlesNewestFirst()` だけを見る。記事の配信自体は `SITE_PAGES`（`site/src/lib/pages.ts`）への登録で決まる。つまり**『一覧に出す』と『URL で配信する』が別の表に分かれている**ので、ドラフトを表現する余地は既にある。

## 決めること: ドラフトの「見えなさ」をどの段階にするか

3 段階あり、どれを採るかで実装も安全性も変わる。

1. **一覧に出さないだけ**（URL を知っていれば読める）… `ARTICLES` に `draft: true` を足し、一覧と sitemap から外す。レビュー用の URL を人に渡せるのが利点。robots.txt / noindex の扱いを決める必要がある
2. **配信もしない**（本番では 404）… `SITE_PAGES` への登録自体を環境で切り替える。確実だが、本番と staging でルート表が変わるため『本番だけ壊れる』経路が生まれる
3. **ファイルは置くが、記事として登録しない**… ビューだけコミットし、`ARTICLES` と `SITE_PAGES` への登録を公開時に行う。**実装は不要**で運用だけで済むが、ドラフトが配信経路に一度も乗らないため、公開の瞬間まで表示崩れに気づけない

**単純化の観点では 3 が最小**（コードを一切増やさない）。ただし『レビューしてもらう』要求を満たせない。1 と 3 のどちらを採るかは、ドラフトを誰に見せたいかで決まるので、着手時にユーザーへ確認する。

## 1 を採る場合に決めること

- **sitemap から外す**。`site/src/routes/public.tsx:225` の sitemap は `SITE_PAGES` 全件を列挙するので、ドラフトを配信するなら除外の判断が要る
- **`REDIRECTED_PATHS`（`site/src/lib/hosts.ts:62`）も `SITE_PAGES` からの導出**。旧ホストからの 301 対象にドラフトが入る
- **『全ページが ja/en の 2 バリアント』の不変条件**（`site/test/articles.test.ts` が固定）をドラフトにも課すか。日本語のドラフトだけ先に置きたい場面はありそうで、その場合は不変条件の例外をどう表現するかを決める
- 検索エンジンに拾わせないなら noindex か robots.txt の Disallow か

## 注意

**この機能自体が『公開しないつもりのものが公開される』事故を作りうる。** 判定を 1 箇所（`Article.draft`）に置き、一覧・sitemap・301 の 3 経路がそこだけを見る形にする。経路ごとに条件を書き写すと、片方だけ直った状態で公開される。
