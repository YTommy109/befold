## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
テストの実行時間を短くしたい。2026-09-29 に全テストを「パラメタ化・過剰な統合テスト・並列化」の 3 観点でレビューし、指摘を原因別のサブタスクに分けた。

## 実測（手元 M 系 Mac / debug ビルド / 2026-09-29）

| 実行 | 結果 |
|---|---|
| `swift test`（並列） | befoldTests 2012 件 wall 44.1 秒、real 47.7 秒、user CPU 54.5 秒 |
| `swift test --no-parallel --skip GitStatusBranchDiffIntegrationTests` | 2008 件 57.0 秒 |
| viewer-test（jest） | 676 件 4.2 秒 |
| site（vitest） | 440 件 wall 6.8 秒 |

**並列でも直列の 1.3 倍しか速くならない。** user CPU（54 秒）と並列 wall（44 秒）がほぼ同じで、CPU を使い切っていない。並列時は各テストの「passed after」が一律 35〜44 秒になる（開始直後に積まれて最後まで待たされている）。約 1900 件の @MainActor テストがメインキューに直列で並ぶことが律速になっている（TASK-607 の観察と同じ構造）。

したがって効くのは次の 3 つ:
1. MainActor 上の重い処理（実 WKWebView・実 NSWindow・ピクセル走査・git 起動）を減らす、または MainActor から外す
2. 固定の sleep / Thread.sleep をゲートや完了待ちへ置き換える
3. CI で同じ swift test を 2 回直列に回している分を並列ジョブへ分ける

直列時の重いスイート上位: FileWatcherIntegrationTests 3.9 秒、ViewerWindowManagerTabTests 2.8、SessionRestorerTests 2.7、ViewerWindowManagerTests 2.6、GitStatusReaderIntegrationTests 2.6、ViewerWindowManagerRecentRepositoriesTests 1.9、ViewerWindowControllerDiffPendingTests 1.6、SidebarChangedFilesOnlyIntegrationTests 1.6。突出した 1 本は無く、長い尾になっている。

## 対応不要と判断したもの
- パラメタ化（観点 1）: `@Test(arguments:)` は既に広く使われている。残る候補は 1 件 1ms 未満で、速度に効くのは重い fixture を共有できるもの（git 系）だけ。そちらは該当サブタスクに含めた
- `BefoldTestSupport/Waiting.swift` の `pollUntil` 50ms 刻み: 呼び出し約 37 箇所、合計 1 秒未満で並列に吸収される
- viewer-test（jest）: loadViewerMain 1 回 15ms 程度、sleep・fake timer 無し。変える余地なし
- site/test（vitest）: 大半は workerd 起動とファイルごとの D1 マイグレーションで並列に消化済み
