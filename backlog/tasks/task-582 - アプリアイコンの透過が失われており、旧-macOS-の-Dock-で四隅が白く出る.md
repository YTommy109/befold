## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
他の人の Mac の Dock で、befold のアイコンだけ四隅に白い部分が見えるとの報告（2026-08-31）。報告者自身の環境では確認できない。

## 実測（2026-08-31）

`BefoldApp/befold/Resources/AppIcon.icns` を `iconutil -c iconset` で展開し、全 10 サイズを調べた。

- PNG の形式は全サイズ RGBA（アルファチャンネル自体はある）
- **アルファ値は全ピクセル 255（完全不透明）。α=0 のピクセルは 0%**
- 四隅の画素は `(255, 255, 255, 255)` = 純白・不透明
- 白い領域は 512px 版で角から対角におよそ 35px。辺の中央 `(256,0)` は背景色 `(44,61,93)`

つまり「四隅だけが白い不透明な正方形」になっている。

元データ `BefoldApp/AppIcon/icon.svg` は正しく角丸で、角の外側は透明（`<rect width="512" height="512" rx="112" fill="url(#bg)"/>`）。**SVG から PNG へ書き出すときに白地へ合成されて透過が潰れた**生成事故であり、デザインの問題ではない。

## 見える環境と見えない環境

- 報告を受けた側の Mac は macOS 26.6.2。macOS 26 は旧来のアプリアイコンを角丸へ自動マスクして表示するため白い角が隠れる
- それ以前の macOS ではマスクが掛からず、白い角がそのまま出る

**未検証**: この OS 側のマスク挙動そのものは実機で確かめていない（macOS 26 機しか手元に無い）。旧 macOS の実機かスクリーンショットで裏を取れるとよい。

## バージョンとの関係

`AppIcon.icns` は `9b6994c4`（2026-07-06 / PR #100）以降 1 度も変わっていない（現行ファイルとバイナリ一致を確認済み）。**「相手が古い版を使っているせい」ではなく、それ以降の全リリースが同じ欠陥を持つ。**

## 着手時の注意

- この環境には SVG ラスタライザが入っていない（`rsvg-convert` / `inkscape` / ImageMagick いずれも無し）。新しい依存を足さずに済ませるなら macOS 標準の WebKit で描画する小さなスクリプトになる
- **再生成の手順を `scripts/` に残すこと。** 手作業で書き出すと同じ白マット事故が再発する
- 別途の判断事項: 現行の角丸矩形はキャンバスいっぱいに描かれており、Apple のアイコンテンプレート（周囲に余白）と違う。余白を入れると他アプリと大きさが揃うが見た目が変わるため、透過の修正とは分けて判断する

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 採用した案（ユーザーの判断 / 2026-08-31）

**案 A: 見た目は現行のまま、透過だけ戻す。** 余白は入れない（キャンバスいっぱいのまま）。

比較用に 3 案を実際に描画して見比べた（現行・A・C=余白 56/1024・B=Apple 従来テンプレート
824/1024）。判断材料として、「Apple のガイド」は macOS 26 で変わっており、余白 824/1024 は
macOS 25 以前の従来テンプレート、macOS 26 は全面に描いた素材をシステムがマスクする方式へ
移っている（＝ A の形のほうが新方式に近い）ことを添えた。befold は macOS 14+ 対象なので
一方だけを正とは決められない。

## 変更

- `scripts/make-appicon.sh` を新設。`BefoldApp/AppIcon/icon.svg` から rsvg-convert で
  10 サイズを透過つきで書き出し、`iconutil` で `.icns` に固める。
- `scripts/check-icon-alpha.py` を新設。書き出し直後に**四隅の α と透明画素の割合**を検査して
  落とす。PIL に依存しない最小の PNG デコーダを持つ（この環境に PIL が無いため）。
  検査を生成の内側に置いたのは、書き出し系がオプション 1 つで無音に白マットへ倒れるため。
- `BefoldApp/befold/Resources/AppIcon.icns` を再生成。

## 検証（実測 / 2026-08-31）

スクリプト内の検査とは**独立に**、出来上がった icns を展開して測り直した。

| 項目 | before | after |
| --- | --- | --- |
| 512px の四隅 | `(255,255,255,255)` | `(0,0,0,0)` |
| 辺の中央 (256,0) | `(44,61,93,255)` | `(43,60,92,255)` |
| α=0 の画素 | 0% | 4.0% |
| 収録サイズ | 10 種 | 10 種 |
| ファイルサイズ | 1,911,711 B | 791,328 B |

辺の中央の色がほぼ同じ（1 の差は再ラスタライズ由来）なので、**図案は変わっていない**。
256px の描画を目視でも確認した。

`xcodebuild` でビルドし、`befold.app/Contents/Resources/AppIcon.icns` が新しいものと
バイナリ一致することを確認、アプリを再起動した。

## 未検証

- **旧 macOS（26 未満）の Dock での見え方は確認できていない**（手元が macOS 26.6.2 のみ）。
  報告者の方に再確認してもらう必要がある。AC #4 はそのため未チェックのまま残す。
- macOS 26 が旧来アイコンを自動マスクするという説明自体も実機検証していない。

## AC #4 を落とした（2026-08-31）

もとの AC #4 は「旧 macOS（26 未満）での見え方を実機かスクリーンショットで確認した結果を
Notes に記録している」だった。これを**確認せずに落とす**。

理由: この不具合はユーザーからの報告ではなく、オンライン会議で共有された画面を見て
気づいたもので、**確認を依頼できる相手・機会が当分無い**（ユーザーの判断 / 2026-08-31）。
手元の Mac は macOS 26.6.2 のみで、自分では旧 macOS を用意できない。

満たせない基準を残すとタスクが永久に閉じられないので、代わりに**何を根拠に直したか**を
ここに残す。直したことの正しさは実機の見え方ではなく、**画像そのものの測定**で担保している
——四隅が `(255,255,255,255)` から `(0,0,0,0)` になり、辺の中央の色は変わっていない。
これは OS のバージョンに依存しない事実で、旧 macOS で白い角が出る条件（不透明な角）は
消えている。

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
アプリアイコンの透過を復元した。出荷中の AppIcon.icns は全ピクセル α=255 で四隅が純白——元データ icon.svg は角丸で角の外側が透明なので、SVG から PNG への書き出しで白地へ合成された生成事故だった。macOS 26 は旧来アイコンを自動マスクするため手元では気づけず、それ以前の macOS の Dock でだけ白い角が見えていた。見た目は変えず（案 A: 余白を入れず現行のまま）透過だけを戻し、実測で四隅 (255,255,255,255) → (0,0,0,0)、α=0 の画素 0% → 4.0%、辺の中央は (44,61,93) → (43,60,92) でほぼ不変であることを確認した。再発防止に scripts/make-appicon.sh と scripts/check-icon-alpha.py を新設し、書き出し直後の透過検査で落とすようにした。旧 macOS 実機での確認は機会が無いため実施していない（AC から外した理由を Notes に記録）。
