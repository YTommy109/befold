## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
1 ページに詰め込まれたダッシュボードを目的別のページへ分け、1 回の表示で発行する D1 クエリ本数の上限をページ単位で持てるようにする。

## 現状（実測、2026-08-16）

- **1 ページに 12 セクション。** `site/src/views/dashboard.tsx` の `<h2>` を数えた実測値。累計 / 本日 / 日毎の推移 / 日別のユニークアクセス元 / 時間帯分布 / 内訳 / 稼働中のアプリバージョン / ページ別の訪問 / 言語別の訪問 / 配布ホストと旧経路 / 人間の訪問と自動アクセス / 最新イベント。
- **1 回の表示で 13 クエリ。** `summarize()`（`site/src/analytics.ts:884-937`）が `Promise.all` で発行する。上限は `site/test/query-count.test.ts:44` の `MAX_QUERIES = 13` で、**現在ちょうど満杯**。
- **上限に空きが無いため、指標を足すたびに既存クエリの畳み込みが要る。** 実際 TASK-491.2 は os / as_org の 2 本を `UNION ALL` で 1 本に畳んで枠を空けてから稼働バージョン分布を入れた（経緯は `site/test/query-count.test.ts:6-43` のコメントに履歴として残っている）。TASK-493（アップデートの取り込み）と TASK-495（GitHub フォールバック配信）も同じ壁に当たる。
- **ルーティングは 2 本だけ。** `GET /dashboard` と `GET /dashboard/stream`（`site/src/routes/dashboard.tsx:74-139`）。認可は Cloudflare Access JWT のミドルウェア（同 `:42-72`）。SSE は `summarize()` を再実行して `renderSummarySections()` の HTML で `#summary` を丸ごと置換する（同 `:124-128`）。

## この分割で何が変わるか

`MAX_QUERIES` の目的は性能上限ではなく「**指標を 1 つ足すたびにクエリが 1 本増える**形への退行検知」（TASK-423 で 19 → 13 に畳んだ経緯が上記コメントにある）。ページを分けても、この退行そのものは防げない。**したがって上限テストは撤去せず、ページごとの上限へ作り替える。**

## 決めること

- **ページの切り方。** 12 セクションを何面に分けるか。案: 概要（累計・本日・日毎の推移）/ 利用者（日別ユニーク・稼働バージョン・時間帯）/ 流入（内訳・ページ別・言語別）/ 配信（ホストと旧経路・フォールバック）/ イベント一覧。目的で分けるのか、更新頻度（全期間累計 か 直近 N 日）で分けるのかを決める。
- **SSE をどのページで動かすか。** 現在は `#summary` 全体を置換する 1 本。ページごとに部分置換へ変えるか、ライブ更新はトップだけにするか。
- **`summarize()` を分けるか。** 現在は全指標を 1 関数で取る。ページごとに必要な集計だけを引く形にすると、関数が面の数だけ増える。共通の型（`Summary`）を保ったまま部分取得にするか、面ごとの関数へ割るかを決める。
- **上限テストの作り替え方。** ページごとに `MAX_QUERIES` を持つのか、全ページの合計に上限を置くのか。「面を増やせば上限を回避できる」形になっていないか。
- **ナビゲーション。** 面をまたぐ導線をどう出すか。Cloudflare Access の認可はどの面にも掛かる必要がある。

## 注意

- **認可を落とさない。** 新しいルートも `dashboardRoutes` 配下に置き、Access JWT のミドルウェアを必ず通す（`site/src/routes/dashboard.tsx:42-72`）。
- **ボット除外の集約点を壊さない。** `HUMAN_ONLY` が 1 箇所に集約されていることは規約テスト（`site/test/analytics.test.ts:519-541`）が担保しており、これは `analytics.ts` の**ソース文字列**を検査する形。`site/src/analytics.ts` を複数ファイルへ分割すると、この検査が分割後のファイルに届かなくなる（`site/vitest.config.ts:24` が `analytics.ts` 1 ファイルだけを `TEST_ANALYTICS_SOURCE` として渡している）。集計 SQL の置き場を動かす場合は、検査の対象範囲を同時に直す。
- TASK-492（最新イベントの専用ページ）は、この分割の一部として吸収できる可能性がある。分割の設計時にどちらで扱うかを決める。
- 経路（ルート・関数）を増やす変更のため、実装着手前に `/review-design` を 1 回回す。
