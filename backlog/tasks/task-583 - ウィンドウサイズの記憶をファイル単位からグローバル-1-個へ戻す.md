## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ユーザー報告（2026-09-01）: ウィンドウサイズをうまく覚えてくれない。最後に調整した値がグローバルに保存され、次にファイルを開くときに参照される仕様のつもりだった。

## 現状（実測 / 2026-09-01）

`WindowFrameStore.initialFrameDescriptor(for:lastActivePathKey:)` の優先順位は
(1) そのファイル自身の保存値 → (2) 直近アクティブだったファイルの保存値 →
(3) `WindowFrameLastUserAdjusted`（app-global） → (4) 既定 1100x850 + center。
グローバル値は 3 番目のフォールバックでしかない。

さらに `ViewerWindowManager+OpenViewer.makeController` が解決結果をその場で
`setFrameDescriptor` で書き戻すため、一度開いたファイルは以後ずっと段 1 で止まり、
後からグローバル値が変わっても反映されない。

手元の UserDefaults 実測: `WindowFrames` に 104 件、`WindowFrameLastUserAdjusted` は
1441x1016。104 件中グローバル値と一致するのは 1 件のみ。

## 経緯（重要）

`backlog/completed/task-74`（Done / 2026-07-19）で、**app-global の単一共有キーを廃止して
ファイル単位に変えた**。きっかけはユーザー指摘「複数ウィンドウを開いて再起動すると、
両方とも同じウィンドウサイズで復元される」。つまり今回の要望はその判断を巻き戻すもの。

方針はユーザーが選択済み（2026-09-01）: **グローバル 1 個に戻す**。TASK-74 の懸念
（再起動時に全窓が同じサイズになる）が再燃しうる点は伝えたうえでの判断。

## 併せて見つかっている別の不具合（本タスクの範囲外にするか要判断）

- タブで開いたファイルには「解決時点の値」が記録されるが、実表示はタブ親の枠で食い違う
- タブ/複数窓を一括で閉じると各窓が同じグローバルキーを後勝ちで上書きし、順序は AppKit 依存

## 文書の是正（本タスクに含める）

- `docs/dev/native-app-design.md` のストア一覧に `WindowFrameStore` の行が無い
- `docs/dev/rules/product-code.md` に廃止済みの旧方式（ウィンドウ autosave 名 Viewer-<パス>）が残っている
- ADR 0001 の表に「URL 単位のウィンドウフレーム永続化」とあり、変更後は実態と食い違う

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
## /review-design の結論（2026-09-01）

ユーザーの判断 2 件で設計が確定した。
1. 新規に開くときはグローバル値。**再起動のセッション復元だけは窓ごとのサイズを保つ**
2. グローバル値を書くのは**リサイズ確定時のみ**（閉じたときは書かない）

### 値の置き場を「窓の状態」と「アプリの好み」に分ける

ADR 0002 の 3 分類（アプリの好み / 文書の状態 / 窓の状態）に沿わせる。
現状の `WindowFrames`（ファイル単位）は、どちらでもない中途半端な置き場だった。

| 用途 | 置き場 | キー |
| --- | --- | --- |
| 新規ウィンドウの出発点（アプリの好み） | `WindowFrameStore` を app-global 専用に縮める | `WindowFrameLastUserAdjusted`（既存・そのまま） |
| 再起動時に各窓を戻す（窓の状態） | `SessionLayout.TabGroup` に `frame: String?` を足す | `SessionLayout`（既存・Codable なので追加は後方互換） |

`SessionLayout.TabGroup` は「窓 1 枚」に対応しているので、フレームの持ち主として素直。
`ViewerTabGrouping.makeTabGroup` が窓から `frameDescriptor` を読んで詰め、
`SessionRestorer.restoreTabGroup` が復元時に適用する。記録は終了時の一括
（`AppDelegate` → `currentSessionLayout()`）なので、windowWillClose の順序に依存しない。

### 消えるもの

- `WindowFrames`（ファイル単位の辞書）と `PathKeyedDictionary` の利用
- `WindowFrameStore.frameDescriptor(for:)` / `setFrameDescriptor(_:for:)` /
  `initialFrameDescriptor(for:lastActivePathKey:)` / `migrateFrameDescriptor(from:to:)`
- `PerFileStateStore` から `windowFrame` を外す（doc に「ファイル毎に永続化する状態の束」と
  あり、app-global 値の置き場として不適切）。`migrate` からも外れる
- `ViewerWindowManager+OpenViewer.makeController` の「解決結果を書き戻す」処理
  （これが 104 件のファイル別記録を作り、グローバル値が届かない原因だった）

### UserDefaults キーの廃止（CLAUDE.md の規定）

`WindowFrames` は読み手が 0 になる。**移行しない**——104 件のファイル別記録を
グローバル 1 個へ畳む意味が無い（どれを選ぶかに根拠が無い）。
既存の合流先 `AppStores.retiredDisplayStateKeys` へ `"WindowFrames"` を 1 行足し、
`removeRetiredDisplayStateKeys` が削除する。テストは `RetiredDisplayStateKeysTests` が
旧値あり／旧値なし／一覧の縮みを既に見ているので、そこへ足す。

### 手順

1. ADR を書く（TASK-74 の判断を上書きする理由を残す）
2. `SessionLayout.TabGroup` に `frame: String?` を足し、`filtered(to:)` で持ち回る
3. `ViewerTabGrouping.makeTabGroup` で `window.frameDescriptor` を詰める
4. `SessionRestorer.restoreTabGroup` で復元時に適用する
5. `WindowFrameStore` を app-global 専用に縮める
6. `ViewerWindowController+WindowDelegate` の保存契機を `windowDidEndLiveResize` のみにする
   （`windowWillClose` からの保存をやめる）
7. `ViewerWindowManager+OpenViewer` の解決を「グローバル値 → nil」に単純化
8. `PerFileStateStore` から `windowFrame` を外す
9. `AppStores.retiredDisplayStateKeys` に `"WindowFrames"` を足す
10. テストを書き換える（`WindowFrameStoreTests` の 4 段フォールバックは消える）
11. 文書を直す（`native-app-design.md` にストアの行を足す / `product-code.md` の旧 autosave 記述を消す /
    ADR 0001 の「URL 単位のウィンドウフレーム永続化」を実態に合わせる）

### 粒度を守らせるもの（項目 9）

- 「新規に開くときファイル別の値を読んだら落ちる」テスト（`WindowFrames` に値を仕込んでも
  グローバル値が使われる）
- `WindowFrameStore` から URL を引数に取る API を**消す**ことで、ファイル単位で読む書き方が
  そもそもコンパイルできない形にする（doc コメントで守らせない）

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 実装（2026-09-01）

設計レビューの結論どおり、値の置き場を 2 つに分けた。

| 関心 | 置き場 |
| --- | --- |
| 新しい窓の出発点 | `WindowFrameStore`（`WindowFrameLastUserAdjusted` 1 個） |
| 再起動時に各窓を戻す | `SessionLayout.TabGroup.frame` |

- `WindowFrameStore` から URL を引数に取る API を全部消した（粒度を型の形で守る）
- 保存契機を `windowDidEndLiveResize` のみにし、窓は保存先を持たず delegate
  （`viewerWindow(_:didAdjustFrameTo:)`）で上位へ渡す形にした
- `ViewerWindowManager+OpenViewer` の「解決結果を書き戻す」処理を撤去——これが
  104 件のファイル別記録を作り、グローバル値が届かなくしていた張本人
- `PerFileStateStore` から `windowFrame` を外した（doc に「ファイル毎に永続化する状態の束」と
  あり、app-global 値の置き場として不適切だった）。rename の `migrate` からも外れる
- `WindowFrames` は移行せず `AppStores.retiredDisplayStateKeys` へ入れて削除

## テストが空振りしないことを 3 通りの破壊で確認

- グローバル値を読まないようにする → `ViewerWindowManagerTests` が 3 件落ちる
- `filtered(to:)` で frame を落とす → `SessionLayoutTests` が落ちる
- 閉じたときにも通知する → `ViewerWindowControllerTests` が落ちる

いずれも復元後は緑に戻ることを確認した。

## 検証（実測 / 2026-09-01）

- `swift test`: 1847 tests / 301 suites 通過
- swiftlint: `origin/main` との差分で**真の新規ゼロ**。既存違反が 2 件解消
  （`WindowFrameStore` と同テストの `opening_brace`）。初回は `MockedViewerWindowManager` の
  init が 2 行増えて `function_body_length` に触れたため、`makeStoreFactory` を外へ出して解消
- markdownlint / check-doc-symbols / check-doc-citations: 通過
- `xcodegen generate` 実行済み
- **実機**: ビルドして起動し、`WindowFrames` の 104 件が defaults から消え、

## 未検証

複数窓を開いた状態でアプリを終了し、再起動して**各窓が前回の寸法へ戻る**ことは実機で
確認していない（セッション復元を伴う手動確認が要る）。ユニットテストでは
`SessionLayout` の持ち回りと Codable 後方互換までを固定している。

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
ウィンドウ寸法の記憶をファイル単位からアプリ全体 1 個へ戻した。原因は WindowFrameStore の解決順でグローバル値が 3 番目のフォールバックでしかなく、さらに窓を開くたびに解決結果をそのファイルへ書き戻していたこと（実測: 記録 104 件のうちグローバル値と一致するのは 1 件）。新しい窓の出発点は WindowFrameStore が 1 個だけ持ち、再起動時に各窓を戻す寸法は SessionLayout.TabGroup.frame（窓の状態）へ移した。保存契機はリサイズ確定のみにして、窓を閉じる順序への依存を消した。URL を引数に取る API を消すことで粒度を型で守っている。TASK-74 の判断を上書きするため ADR 0010 / decision-10 を残した。swift test 1847 件通過、swiftlint 新規ゼロ（既存 2 件解消）、実機で旧キー 104 件の削除とグローバル値の存続を確認。
