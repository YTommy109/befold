## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ADR 0002 の Consequences 末尾「この決定を再検討するトリップワイヤ」の 3 番目に「複数ウィンドウ間で提示状態を共有・同期する要件が生まれる」がある。TASK-371（同一ファイルを複数ウィンドウで開いた際の表示モード同期）でこの条件は既に発火しており、実際に ViewerWindowController.setDisplayMode → delegate → ViewerWindowManager.mirrorDisplayMode という窓間同期の経路が実装された。トリップワイヤを引いた以上、発火を放置せず一度決定を再検討する必要がある（TASK-377 で遷移仕様を追記した際に気付いた）。

再検討で答えるべき問い:
- 現行の決定（提示状態を 1 値で持ち能力を導出する / フレームワークは導入しない）は、窓間同期という新しい要件のもとでも維持できるか
- 同期対象が表示モード 1 種で済むのか、今後スクロール位置・ズーム・行番号表示などへ広がるのか（広がるなら窓ごとの状態とアプリ全体で共有する状態の線引きをどこに置くか）
- 現行の実装（デリゲート経由の同期呼び出し・パスキー引き・永続化する選択のみ同期）を ADR に正式な決定として書くのか、別 ADR を起こすのか
- トリップワイヤ 1（提示していない対象への書き込みの再発）と 2（分岐が手書きで追えない規模）の現状も併せて評価する

結論が「決定を維持する」であっても、トリップワイヤの文面を更新する（発火済みであることと、その上で維持した理由を残す）。

## 再検討の結論: 決定を維持

トリップワイヤ 3 本の現状を Explore サブエージェント 2 本でコード実測し（段 1〜5 の進捗 / 状態の粒度の全数調査）、その結果を ADR へ反映した。

判定:
- トリップワイヤ 1（段 1〜3 後の回帰再発）= 前提未成立。段 1 は PreviewTarget に .undetermined が入り誤無効化は解消したが、対象の格納は ViewerStore.currentURL/filePath と FileListModel.selection の 2 系統が残る。段 3 は初期値が makeNSView → atDocumentStart のユーザースクリプトに残存（ViewerWebView.swift:73-76 → ViewerRenderer.swift:163-190）
- トリップワイヤ 2（分岐が追えない規模）= 未発火。表示モードの遷移は 5 関数に閉じ、降格規則は DisplayModeStore（102 行）の 1 箇所
- トリップワイヤ 3 = 発火済み（TASK-371）
- 段 2・4・5 は実装済み（ViewerCapabilities.swift:12-85 / DocumentRendering.swift:11-42 / ViewerRenderer+ContentUpdate.swift:99）。段 2 が名指しした「validateMenuItem を通らない 4 経路」は解消または対象外

維持の根拠: 同期対象が 1 個の値だったため同期経路が 1 本（setDisplayMode 完了後のデリゲート → パスキー引き）で済んだ。規約 1 が窓間同期を難しくするのではなく可能にしていた。

## 実装ではなく基準の一般化を選んだ理由

再検討の過程で「窓間で揃えるべき状態とそうでない状態」の線引きが表示モードにしか書かれていないことが分かった。個別に決め続けると場当たりになるため、判定質問（同一ファイルを 2 窓で開いて食い違って見えたらバグか）と 3 分類（文書の性質 / 利用者の好み / 窓の操作履歴）へ一般化した。分類は既存実装から帰納したもので、DiffDisplayPreference.swift の doc コメント（好みの設定 vs ファイル固有の性質）が既に同じ区別をしていた。

基準を既存状態へ当てて逸脱 3 件を発見し、TASK-388 / 389 / 390 として起票（ユーザー承認済み・修正は本タスク外）。
