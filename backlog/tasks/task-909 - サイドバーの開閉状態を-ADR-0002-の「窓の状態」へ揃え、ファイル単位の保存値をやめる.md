## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
サイドバーの開閉は文書に紐づかず、ADR 0002 の分類では「窓の状態」にあたる。しかし `SidebarStateStore.initialCollapsed` は 2026-07-19 の実装のまま「そのファイルの保存値 → 直近アクティブなファイルの保存値 → 最後の操作」の順で解決する（ADR に「窓の状態」が足されたのは 2026-08-14 で、例示は表示設定 4 値のみ）。さらに窓を開くだけで解決結果が `setCollapsed` でファイルへ書かれる。その結果、以前に閉じた状態で開いたファイルは、別の窓でサイドバーを開いた後でも、再起動や開き直しで閉じたまま始まる（コードからの判断で未再現）。意図する動作は、開いている間はウィンドウ単位、再起動時は最後のユーザー操作の保持。PR #750 が同じ `openViewer` に手を入れているため、取り込み後に行う。
<!-- SECTION:DESCRIPTION:END -->

- [x] #5 旧キー SidebarCollapsedStates の読み手が 0 になり、移行するか否かの決定が Notes にあり、旧キーが defaults から削除される（CLAUDE.md「UserDefaults キーの廃止・改名」のテストを含む）

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
方針: 開閉状態を ADR 0002 の窓の状態として扱う。ライブ値は窓ごと（既存の sidebarItem）、保存値はアプリ全体に 1 つ（SidebarLastToggledCollapsed）で新規窓の初期値にだけ使う。
1. SidebarStateStore を lastToggledCollapsed と recordToggle(_:) だけにする。ファイル単位の辞書・setCollapsed・isCollapsed・initialCollapsed・migrateCollapsed を削除
2. PerFileStateStore から sidebar を外し、ViewerWindowDependencies が sidebarState を直接持つ（ファイル単位ではないため）
3. ViewerWindowOpenPolicy.initialSidebarCollapsed の解決順を 種別 > CLI > フォルダー強制 > 起点の窓の現在値（.newTab のみ）> 最後の操作 にする。sourceCollapsed は必須引数
4. 起点の値は『表示前なら initialCollapsed、表示後なら sidebarItem.isCollapsed』を返す読み取り口から取る（背面タブが起点になる複数ファイルのドロップで初期値と食い違わないように）
5. 記録を toggleSidebar（利用者の操作）だけにする。setSidebarCollapsed（CLI・フォルダー強制）は開閉とフォーカスの後始末は共有するが記録しない
6. 旧キー SidebarCollapsedStates は移行しない（ファイルごとの値のどれを全体の値に選ぶかに根拠が無く、SidebarLastToggledCollapsed が既に残っている）。retiredDisplayStateKeys へ追加
7. ADR 0002 の窓の状態へ開閉を追記し、docs/dev を更新
8. テスト: 解決順の純粋テスト、新タブが古い保存値に左右されない、再起動相当で最後の操作、CLI・強制表示が記録を書き換えない、旧キーの削除
再起動時の扱い: 全窓を最後の操作の値に揃える（2026-11-07 のユーザー発言「再起動時は最後のユーザー操作の保持」と ADR 0002 の窓ごとに永続化しない方針に基づく）。
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
未決（着手前に確認）: 再起動で複数の窓を復元するとき、全窓を最後の操作の値に揃えるか、窓ごとの値を TabGroup に持たせるか。ADR 0002 は窓ごとの永続化をしない方針なので前者を想定している。状態の持ち方を変える変更なので着手前に /review-design を回す。

決定: 再起動時は全窓を最後の操作の値に揃える（ユーザー発言と ADR 0002）。旧キー SidebarCollapsedStates は移行しない（ファイルごとの値のどれを全体の値に選ぶかに根拠が無く、全体の値は SidebarLastToggledCollapsed に既にある）。削除は AppStores.retiredDisplayStateKeys。
挙動の変更（意図どおり）: フォルダーオープンの強制表示と CLI の --sidebar は保存値へ書かない。そのためフォルダーを開いて強制表示された窓も、再起動後は最後の操作の値で始まる。
実測: 修正を戻すと落ちることを確認（setSidebarCollapsed の記録 → onlyUserTogglesAreRecorded、表示前の値 → resolvedStateBeforeAppearanceIsInitialValue、.newTab の条件 → newWindowIgnoresSourceWindow、起点の値を無視 → newTabFollowsSourceWindow と initialSidebarCollapsedResolutionOrder）。swift test --skip befoldCLITests --skip PDF 1972 件成功、--filter PDF 103 件成功、xcodebuild 成功。swiftlint 新規 0 件、既存 1 件解消（SidebarStateStore の opening brace）。
責務レビュー: PerFileStateStore はメンバーが倍率だけになったので畳んで ZoomStore を直接注入した。sidebarState は ViewerWindowController に保持せず組み立て時に渡す（グループ 938 行、例外上限も 938 へ更新）。
レビューで挙がった範囲外の疑い（未再現、今回の変更より前から）: 表示前の背面タブへ CLI の --sidebar を当てても、後の viewWillAppear が initialCollapsed で上書きする可能性がある。
現在仕様: ADR 0002 と native-app-design.md を更新した。実機では未確認で、開閉の実動作は確認していない。
