## 差し替える情報（実ファイルに含まれるもの）

- 氏名: 姓 1 つと名 2 つ。person 列・ファイル名規約・『妻への説明』節に散在

## 匿名化は機械的な置換では済まない

氏名の書き分け規約が『person 列は姓名を空白区切り / ファイル名は空白なし / 領収書ファイル名は名のみ』の 3 通りで、**領収書だけ名のみなのは姓が全員同じで区別に寄与しないから**という理由に依存している。架空名でもこの構造が成立する組み合わせを選ぶこと。想定は架空の 4 人家族。

## 落とす節

- Dropbox / iCloud の比較検討（『なぜこの構成にしたか』のうち Dropbox + file request 案、iCloud を選んだ理由）。焦点がぶれる上に個人情報を含む
- summary-YYYY-氏名.tsv の例外（明細が残っていない年がある、という家庭の内情）

## 残す価値が高い節

- フォルダ構成と『なぜ data/ に分けるか』『なぜ Inbox を年で分けないか』（設計の理由が読者の判断材料になる）
- TSV の列仕様と、category を医療費控除の明細書の 4 区分に対応させてある設計意図
- 領収書の保存義務（スキャンしても紙は 5 年保存。電子帳簿保存法のスキャナ保存は給与所得者の医療費控除には及ばない）。**ここは誤解が多く、記事の価値が高い部分**
- 読み取り手順（pdfimages → Pillow の autocontrast → pypdf で分割）
- 『妻への説明（これだけ）』相当の、投入する側に渡す 3 行

## 実装（2026-08-22）

置き場: `site/public/templates/medical-expenses/{CLAUDE.md,README.md}`

site/public を選んだ理由:

- markdownlint の globs `site/**/*.md` に入るので、テンプレートも校正の対象になる（実測: 新規 2 ファイルとも指摘 0 件）
- 静的アセットとして配信されるため（`site/src/index.ts` の ASSETS 委譲）、TASK-538.4 の『読者が持ち帰る導線』にそのまま使える

架空の家族: 北原 健吾 / 北原 沙織 / 北原 悠真 / 北原 芽衣。**姓を 4 人とも同じにし、名を 4 つとも重複しないようにした**——氏名の 3 通りの書き分け（person 列は空白区切り / ファイル名は空白なし / 領収書は名のみ）のうち、領収書だけ名のみで済むのが『姓が全員同じで区別に寄与しない』という理由に依存するため。テンプレートとして配る以上その前提が崩れる読者がいるので、『家族に同じ名の人がいる場合はこの規約が成立しない』という但し書きを足した。

医療機関名・住所・電話は**架空名への置換ではなく記入例**にした（`〇〇クリニック` / `〇〇県〇〇市〇〇 1-2-3` / `0XX-XXX-XXXX`）。架空の固有名詞は実在するかの確認が必要になるうえ、テンプレートとしては記入例のほうが用途に合う。
