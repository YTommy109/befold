## Context

本決定の記録は `docs/adr/0011-legacy-distribution-shutdown-conditions.md` にある。
実測値・指標の限界・担保の一覧はすべて ADR 側を参照すること。
実装タスクは TASK-489.1（親 TASK-489。判定の実施は TASK-489.4）。

ADR 0007（decision-7）は旧ホストの恒久併存を決めたが、停止条件を
「観測できてもゼロを保証できない」と書いたまま停止時期を定めなかった。
本決定はその空白を埋めるもので、**ADR 0007 の更新であって supersede ではない**。
0007 の決定 2〜6 はすべて有効なまま残る。

## Decision

旧世代の配布経路を 4 つに分け、それぞれに別の停止条件を持たせる。ひとつの
「停止」に畳まない（リスクの大きさが桁違いに違うため）。条件の形は共通で、
**「指標が人間分ゼロ + 継続期間 + 切り捨てを受け入れるバージョン範囲の明示」**
とする。ゼロは観測できてもゼロを保証しないため、「ゼロが続いたら止める」ではなく
「ゼロが続いたうえで、切れても構わないと判断する版を明示して止める」形にする。

1. **新規リリースでの GitHub Releases への DMG 添付をやめる**: `github_fallback` の
   `dmg` が人間分 90 日連続ゼロ、かつ現行 appcast の全 enclosure が R2 にある。
   切れる対象は無し。
2. **固定リリース `appcast` への appcast アップロードをやめる**: GitHub の appcast
   アセットの `download_count` がリリースを 3 回またいで 0、かつ `release.yml` が
   それを入力として使わなくなっている、かつ前回判定から 180 日以上。
   **切れる対象は v1.10.0 以前**（自動更新が永久に止まる）。
3. **過去のリリースアセットの削除**: **原則として削除しない。** 得るものが
   ストレージだけで、失うものが「R2 に無い版を掘り出す最後の手段」という非対称は
   期間を延ばしても変わらない。一括削除のワークフローを作らないことを担保とする。
4. **workers.dev の停止**: `/dl/*` と `/appcast*.xml` を分けて扱う。現行 appcast の
   enclosure が全て `befold.degino.com` を指すため（実測 2026-09-04）、旧ホストの
   `/dl/` を通るクライアントは原理上存在せず、両者はもう連動しない。
   - `/dl/*`: 人間・ロボットとも 90 日連続ゼロ。切れる対象は無し。
   - `/appcast*.xml`（＝ `workers_dev = false`）: `update_check` が人間分
     **90 日連続**ゼロ、かつ `/dl/*` の条件を満たすこと。
     **切れる対象は v1.10.1 〜 v1.12.x**。最短の充足日は 2026-11-19。

90 日とした根拠は 2 つ。切り捨てる母集団が小さいこと（この世代 11 リリースの
GitHub DMG ダウンロード合計 19 件。実人数は数人規模）と、**90 日を超えて
観測されない使い方では自動更新そのものが機能を果たしていない**こと（起動しない
限りチェックも更新も走らないため）。観測されない人を守るために経路を維持する
理屈は、その人が経路から利益を得ている場合にのみ成立する。

条件を満たしたかの判定は TASK-489.4 で四半期に 1 回行い、満たさなかった場合も
タスクを閉じずに次回判定日を Notes へ書いて To Do に戻す。「気づいたときに見る」
形にしない（それが ADR 0007 の決定 1 に起きたこと）。

## Consequences

どの条件も「ゼロを保証」しない。観測されない利用者を切ることを、バージョン範囲を
明示したうえで判断として引き受ける形になっている。

GitHub の `download_count` はリリースのたびに 0 へ戻る（`gh release upload --clobber`）
ため、条件 2 だけは期間ではなくリリース回数で数えるという歪んだ形になっている。
また `events.host` 列は 2026-08-16 以降にしか無く、すべての継続期間はそれ以降で
しか数えられない。

判定を四半期 1 回のタスクに預けるため、条件を満たしてから実際に止まるまでに最大
90 日の遅れが出る。止めることに緊急性が無いので許容する。決定 4b は「90 日開いた
利用者は自動更新から利益を得ていない」という解釈に乗っており、反例を否定できない
ことは受け入れる。
