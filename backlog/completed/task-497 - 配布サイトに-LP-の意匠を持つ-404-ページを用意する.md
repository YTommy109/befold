## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-496 の設計レビューで切り出した。

現状 `site/public/` には `carousel.js` / `style.css` / `images/` しか無く、ルートに当たらないパスは `site/src/index.ts:43` の `app.notFound` から `c.env.ASSETS.fetch` へ落ちて、静的アセットの素の 404 が返る。

TASK-496 で言語ごとの URL（`/en` 系）を足すと、`/en/download` や `/ja` のような「ありそうで無いパス」が増え、404 への到達確率が上がる。LP と同じ意匠で、日本語・英語それぞれの入口へ戻せる 404 ページを用意する。

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
## 設計判断

**D1. 404 は言語ごとに分けず、1 枚のバイリンガルページにする。** LP は URL が言語の唯一の持ち主（TASK-496 の D5）だが、404 に来るパスは定義上 SITE_PAGES に無く、どの言語で書かれた URL かを信頼して決められない（/en の打ち間違いも /features の打ち間違いも同じ経路に来る）。/404 と /en/404 を作ると、どちらを出すかの判定を再びパスの形から推測する必要が出る。日英を両方書き、両方の入口へリンクする（AC#3 もその形を求めている）。

**D2. PageShell は使わない。** PageShell は canonical・hreflang・og:url・og:locale を entry から必ず出す。404 は SITE_PAGES のエントリを持たず、canonical を出すと存在しない URL を正規化し、hreflang を出すと対応関係が壊れる。404 専用の最小 head を not-found.tsx に持ち、<meta name="robots" content="noindex"> を付ける。style.css・SiteFooter・CLEANUP_SCRIPT は共有する。

**D3. SiteHeader も使わない。** SiteHeader は言語切替 nav を variantsOf(entry.page) から描くため entry が要る。404 では h1 と GitHub リボンだけを描き、言語導線は本文の 2 ボタンが担う（同じ役割の導線を header と本文に二重に置かない）。

**D4. events には一切記録しない。** visit にしないだけでなく新しい kind も足さない。404 の到達数が要るなら Workers Observability で見る（events は LP の指標のための表で、AC#4 は混入の禁止を求めている）。

**D5. ASSETS への委譲は残す。** notFound で ASSETS.fetch した結果が 404 のときだけ自前の 404 ページに差し替える。先に自前 404 を返すと /style.css・/images/* が配信されなくなる。

## 実装手順

1. site/src/views/not-found.tsx を新設。NotFound FC（バイリンガル本文 + pathFor('/', 'ja') / pathFor('/', 'en') への 2 ボタン + noindex）。
2. site/public/style.css に .not-found-links（横並び・折り返し）を追加。ほかは既存クラス（.hero / .btn-primary / header / footer）を流用する。
3. site/src/index.ts の app.notFound を、ASSETS の応答が 404 のときだけ NotFound を 404 で返す形にする。recordEvent は呼ばない（理由をコメントに残す）。
4. site/test/public.test.ts に 404 のテストを追加: (a) 未定義パスは 404 で LP の意匠（style.css を参照）を返す、(b) 日本語・英語両方の入口へのリンクがある、(c) noindex が付く、(d) events に行が増えない、(e) 実在アセット（/style.css）は 200 のまま。
5. npm run lint / format:check / typecheck / vitest を通す。

## /review-design の結果（実装前）

- **項目 1（判定の真実の源）**: 404 の判定を「ASSETS の応答が 404 か」という事実で行う。パスの形（拡張子の有無・`/en` 接頭辞）から推測しない。裏付け: `site/wrangler.toml` の `[assets]` に `not_found_handling` が無く既定（none）なので、実在しないアセットは 404 で返る（コード参照: wrangler.toml の assets 節）。
- **項目 2（既存の不変条件）**: (a) ADR 0007 決定 2 の `REDIRECTED_PATHS` は肯定列挙。404 用のパス（`/404` 等）を新設しないので列挙同期は増えない。(b) 計測ページの `Cache-Control: no-store` 不変条件は 404 には適用外だが、404 応答もキャッシュさせない（後からそのパスがページになったときに古い 404 が残らないように `no-store` を付ける）。
- **項目 3（消費経路の全列挙）**: 404 を返す経路は 2 つ。`app.notFound`（site/src/index.ts:52）と旧ホストの `/dashboard`（site/src/routes/dashboard.tsx:69）。後者は機械/管理面で意図的に素の text を返しており、LP 意匠は不要。触らないことを明記する。`/download`・`/dl/:tag/:file`・appcast は 404 を返さず 302/502 に倒れるので対象外。
- **項目 4（新しい状態の表示）**: 404 に固有の文言を日英で用意する。LP の hero 文言を流用しない。
- **項目 7（測るものと守るもの）**: AC#4 は「visit として記録しない」だが、テストは **events の行数が増えないこと**で確かめる（kind を限定して数えると、後から別 kind を足したときに素通りする）。
- **項目 9（決めたことを守らせるもの）**: D4（events に記録しない）は上記テストで担保する。D2（canonical / hreflang を出さない）は「404 応答に `<link rel="canonical">` が無く `noindex` がある」ことをテストで固定する。
- **項目 5・6・8**: 該当しない。非同期の世代管理も高頻度経路も無い（404 は単発の同期的な応答で、ASSETS.fetch 1 回は現状と同じ回数）。項目 10 は Swift の型グループが対象で、この差分は site/ のみ。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 実装

- `site/src/views/not-found.tsx` を新設。`NotFound`（バイリンガル 1 枚・noindex・canonical/hreflang 無し）と、404 応答を組む `notFoundResponse`。
- `site/src/index.ts` の `app.notFound` を「ASSETS の応答が 404 のときだけ自前ページに差し替える」形へ。`recordEvent` は呼ばない。
- `site/public/style.css` に `.not-found-links` を追加（既存の `.hero` / `.btn-primary` / `header` / `footer` を流用し、新規の意匠は作っていない）。
- `site/test/public.test.ts` に `describe('404 ページ')` を追加（6 ケース）。

## 検証（実測）

- `npm test`（site）: 12 files / 343 tests すべて成功。
- `npm run typecheck`: エラーなし。`npm run lint` / `format:check`: 指摘なし。
- **修正を戻して落ちることを確認した。** `app.notFound` を旧実装（`ASSETS.fetch` をそのまま返す）へ戻すと、追加した 6 ケースのうち 4 件が失敗する（意匠・両言語導線・noindex・no-store）。残る 2 件（events に記録しない / 実在アセットは 200）は旧実装でも通るガード用のケースで、これは意図どおり——前者は「404 を記録する実装を入れたら落ちる」、後者は「自前 404 を先に返す実装にしたら落ちる」ことを守っている。

## 設計判断（詳細は Implementation Plan の D1〜D5）

- 404 用の URL（`/404` 等）は作らない。作ると `SITE_PAGES`・`REDIRECTED_PATHS`・sitemap の列挙同期が 1 つ増え、かつ「どちらの言語の 404 を出すか」の判定をパスの形から推測することになる。
- `events` へは記録しない。到達数が要るようになったら Workers Observability で見る。

`site/README.md` に「404 ページ」節を追加し、ルート表に「その他」の行、記録されないギャップの数を 2 → 3 へ更新した。
