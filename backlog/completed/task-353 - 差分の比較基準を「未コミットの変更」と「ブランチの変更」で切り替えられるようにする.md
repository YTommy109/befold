## 背景

差分表示の基準は `merge-base(HEAD, デフォルトブランチ)` から作業ツリーまでで固定されている（`GitComparisonBaseResolver` / `GitDiffReader`、TASK-352 でサイドバーのバッジと統一）。何との差分かを示す表示も、基準を変える手段も無い。

stacked PR（gh-stack）で作業すると、この基準はスタックの根元になるため、**一つ前の PR までの変更がすべて差分に混ざる**。レビューしたいのは「このブランチの PR に載る変更」なので、既定がずれている。また「いま編集した未コミットの変更だけを見たい」場面もある（起票時の動機）。

## 仕様（2026-10-08 に再設計）

基準は 3 つ。差分モードのときだけ、何との差分かを示すラベル兼ポップアップを出して切り替える。

| 選択肢 | 基準 | 備考 |
|---|---|---|
| このブランチの変更（既定） | `merge-base(HEAD, 親ブランチ)` | 親ブランチが分からなければデフォルトブランチ＝今の挙動 |
| スタック全体の変更 | `merge-base(HEAD, デフォルトブランチ)` | 親ブランチがデフォルトブランチと異なるときだけ出す |
| 作業中の変更 | `HEAD` | ステージ済み・未ステージは分けない（閲覧専用アプリでステージしないため、区別はバッジで足りる） |

- **親ブランチの解決**は TASK-353.1。gh-stack のスタックファイルを読み、無ければデフォルトブランチへ縮退する
- **粒度は窓ごとのライブ値**で、永続化しない（新しい窓は常に既定から始まる）。表示モードも TASK-565 で永続化をやめており、それに揃える
- **サイドバーのバッジは窓の基準に追従する**（TASK-352 の一貫性を保つ）
- 基準ごとに差分が空になりうるので、差分モードの選択可否（`GitDiffAvailability`）も基準ごとに判定する

## 採らなかったもの

- **直前のコミット**: コミット単位の閲覧はマイルストーン m-3（コミット一覧）の範囲に置く。m-3 のリスト先頭エントリには本タスクの 3 基準をそのまま使う想定
- **ステージ済み／未ステージの分離**: 上記のとおり
- **任意のブランチやコミットとの比較**: 需要が確認できていない
- **ツールに依存しない親ブランチの推定**（HEAD の祖先にある最寄りのローカルブランチ）: 同じコミットを指すブランチが複数あると決まらない。gh-stack 以外のスタック運用の需要が出てから

## 分割

- TASK-353.1 親ブランチの解決
- TASK-353.2 基準の切り替え UI と差分ビューア
- TASK-353.3 サイドバーのバッジを基準に追従させる

各サブタスクの着手前に `/review-design` を回すこと（新しい表示状態を足す変更のため）。

## 優先順位の整理(2026-08-10)

TASK-435(git 連携の libgit2 移行)の後段に置いた(ordinal 113000)。本タスクは GitDiffLoader / 比較起点の解決に手を入れる feature であり、435 より先に着手するとバックエンド差し替え時に作り直しになる。435 の着手前に本タスクをやる場合は、その手戻りを承知の上で判断すること。

## 再設計（2026-10-08）

stacked PR で基準がスタックの根元になる問題を受けて、2 択（ブランチ／未コミット）から 3 択（このブランチ／スタック全体／作業中）に作り直した。上の「優先順位の整理」で待っていた TASK-435（libgit2 移行）は完了済みで、`GitComparisonBase` は libgit2 実装になっている。旧版にあった `FeatureGate.isSourceDiffEnabled` 配下という制約は、ゲートがコードから無くなっている（`rg isSourceDiffEnabled BefoldApp` で 0 件）ため削除した。

m-3 との関係: m-3 は「基準切り替えの設定を新設せず、コミット一覧の先頭エントリで両方の見方を出す」としていた。本タスクは窓ごとのライブ値（永続化しない、`DiffDisplayPreference` に値を足さない）として先に出し、m-3 ではこの 3 基準を一覧の先頭エントリとして再利用する想定。そのため milestone から外した。

マイルストーンの差し替え（2026-10-08）: m-3 の説明文は CLI で編集できないため m-3 をアーカイブし、本タスクを第 1 段階に置いた m-11「比較対象を選んで変更を追えるようにする」を新設した。サブタスクも含め m-11 に入れた。

## /review-design（2026-10-08、親で 1 回。各サブタスクの Plan に反映済み）

最大の指摘は、`GitStatusStore`（root キー）と `GitDiffLoader`（ファイルパス キー）が app 全体共有で合流・キャッシュしている点。基準を窓ごとにするならキーに基準を含めないと、窓 A の基準で取った結果を窓 B が受け取る。詳細は 353.2 の Plan。gh-stack のスタックファイルは v0.1.1 が worktree ごとの admin dir、新版が common dir に置く（上流ソースで確認、353.1 の Plan）。

swiftlint は origin/main との差分ゼロ(45件=45件)。残り: 353.2 AC#1 と親 AC#1/#2 はツールバー操作の目視確認待ち(自動化不可)。
