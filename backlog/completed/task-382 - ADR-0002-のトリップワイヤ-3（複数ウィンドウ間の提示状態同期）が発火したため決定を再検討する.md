## 追記（2026-08-09）: ユーザー提案により結論を差し替え

上記の「決定を維持」を提示したところ、ユーザーから代替案が出た。「窓間で同期はしたくない。窓が生きている間はその窓で設定したズームやスクロール位置が有効で、窓を閉じるとその値は無効になりファイル単位の保存値が有効になる、では解決できないか」。

評価した結果、この案を採用した。根拠:
- 実装が小さい。現状すでに「窓ごとのライブ値 + ファイル単位の保存値」の二層になっており、壊れているのは保存値を読み直す契機だけ（ViewerWindowController.swift:491 が再ロード時に applyStoredZoom を呼ぶ）。同期経路を足すのではなく、提示開始時以外は読み直さないようにするだけで済む
- 規則が 1 本になる。ズーム・スクロール・表示モードを同じ扱いにでき、表示モードだけ特別扱いしなくてよい
- 同期の設計で必要だった配慮（無限再帰の防止・ミラー先での永続化抑止・差分取得の合流のための同期区間の制約）がまとめて不要になる
- TASK-371 が採用した「全窓が同じ表示モードを示す」という不変条件は、レビュー指摘（feat/preview_mode の 10 件中 1 件）由来で、この代替案と比較されないまま選ばれていた

ユーザー判断:
- 表示モードにもこの原則を適用する（TASK-371 の同期を撤去する）
- アプリ再起動時に同一ファイルの複数窓が同じ値で復元されるのは許容する（窓 ID を作らない）。SessionLayout は groups: [TabGroup] でパスの並びしか持たず窓の同一性を表す値が無いため、識別子の新設は「同一ファイル複数窓 × 再起動」だけのために行うことになる

## この差し替えで自分の分類が 1 件の偽陽性を出していた

当初 ADR に書いた 3 分類（文書の性質は全窓一致 / 好み / 操作履歴）は既存実装から帰納したものだったが、「文書の性質は全窓一致」が誤りだった。この分類のもとで TASK-389（行番号表示）を逸脱として起票したが、新しい原則では現状の実装（窓ごとのライブ値 + アプリ全体の既定値）がそのまま模範例にあたるため、修正すべきものが無い。TASK-389 は取り下げてアーカイブした。TASK-390（スクロール位置）は TASK-388 へ統合。

## ADR の書き換え内容（追加分）

- 「状態の所在」節を 3 分類から 2 分類（文書の状態 / アプリの好み）へ差し替え。判定質問も「食い違って見えたらバグか」から「別々になっていたら困るか」へ反転
- 「複数ウィンドウの不変条件」節を「複数ウィンドウでの扱い」へ改題し、不変条件を撤回
- 遷移表から「他ウィンドウからの同期」行、永続化規則から mirrorDisplayMode の項、cmd+U の戻り先の破棄条件から同期経路への言及を削除
- トリップワイヤ評価の結論を「決定は維持するが、発火の原因となった同期要件自体を取り下げる」へ変更。再発火条件 3 を「窓ごとの状態の永続化に窓の識別子が必要になったとき」へ差し替え

実装（mirrorDisplayMode の撤去と読み直し契機の限定）は TASK-388 で行う。ADR が先行し実装が追いつく形になる点を ADR 本文に明記した。
